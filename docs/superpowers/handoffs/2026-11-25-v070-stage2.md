## 2. What the review found and what changed

Important, all fixed: reminder mail failed for an `http://` public URL (List-Unsubscribe is https-only now omitted
over http); the IME guard's 50 ms window swallowed Gboard's first Enter (window removed; Safari's keyCode 229 is
what the guard keys on); "Change server" left the old account's alarms armed (native `ServerStore.forget` clears
alarms and notifications); notifications went stale after offline study (stale flag cancels them; 7-day horizon
documented).
Minor, fixed: forgeable `EXTRA_ROUTE` (notification tap now goes through a non-exported `NotificationTapActivity`;
`routeHref` rejects `..`, `%2e`, `//`, backslashes), logout racing a replan, push TTL vs quiet hours, enabling
reminders sending an old slot, dead push endpoints (dropped after 5 failures, per-account deadline), sticky IME
flag, edge-symbol stripping in answers (`C++` ≠ `C`), push subscription kept after session expiry, a secret
rotation re-seal gap, doc/comment drift.
Documented, not changed: a failed send is final for the day; due counts use UTC-hour buckets; lost `QINQIN_SECRET`
needs a manual reset of the push tables (no admin action); reminders stop 7 days after the last app open.

## 3. What the emulator CI covers (Android 14, WebView Chromium 113, software GL)

Core job (~32 steps): shell, bridge, offline start/study, outbox exactly once, sign-in, study with Back,
reader lookup by tap, back-button order, local notification. Extended: page crawl, IME, touch pads, perf.
Cold start to a rendered page 2.4 s, card flip 25 ms, JS heap 12 MB, APK 3.9 MB (scroll jank figures from software
GL are not meaningful). The jobs flake about one run in three on emulator infrastructure (WebView hang, Google
Play services restart, Maven 429); re-run once before trusting a failure. Recommendation from the #37 agent: keep
`core` on path-filtered PRs and consider `extended` nightly/manual only.

## 4. Rulings

Full lists with costs are in each plan's "Review fixes (stage 2)" section and in ADR 0011. Headlines: local
notifications from the server plan, no Firebase/Play (real push only via UnifiedPush or a Play-only flavour
later); the web app stays the single source of every screen; emulator-only checks through adb + CDP, no Playwright.

## 5. What the owner must check on a real phone

Not covered by any run: Gboard (Latin, Pinyin, Japanese) Enter/composition order and handwriting; Samsung keyboard;
alarm delivery under Doze and OEM battery killers, re-arm after reboot and app update; the Android 13+
notification permission flow (deny, "don't ask again", revoke after scheduling); notification tap cold vs warm
and while signed out; "Change server" really clearing alarms (only pure logic is JVM-tested); the save-file
picker if the activity is destroyed underneath it, a large backup's memory use; TTS with no engine installed;
share / "process text" from real apps; keep-awake across rotation; vibration with system haptics off; camera/gallery
via system apps; real phone performance. Hand checklists: `docs/superpowers/checklists/android-ime.md`,
`android-pages.md`.
