# #293 — the logo in the phone's top bar in bottom-bar mode (2026-11-27)

Milestone v0.9.0, phase 1 (foundations and bugs). Branch `feature/v090-293-phone-logo`.

## What

In bottom-bar mode (#188) the phone's top bar (`lib/frame/PhoneBar.svelte`) starts with the section's name
(`phoneTitle()`), which repeats what the bottom bar already marks. Show **the qinqin logo** there instead, a link
to Home, as the desktop top bar does (design §9). Owner decision (2026-11-26): **just the logo, on every page in
bottom-bar mode**, including pages with their own title (an entry, a journal entry); those titles stay as the
page's own heading. Drawer mode is unchanged (menu button and title).

## Rulings

- Ruling: the link's name is `nav.brand.home` ("qinqin, home"), the desktop brand link's name — the issue names
  that key; one name for the same link in both frames — cost if wrong: a catalogue change.
- Ruling: no tooltip on the phone logo, unlike the desktop brand — a tooltip needs hover, there is none on a phone,
  and the link has an accessible name — cost if wrong: none.
- Ruling: the mark is 2rem (32 px) inside a 2.75rem (44 px) square link — the bar is 3rem high; 44 px is the
  minimum touch target the issue asks for; the desktop mark (40 px in 2.5rem) would fill the bar edge to edge —
  cost if wrong: a size change.
- Ruling: no new h1 is needed — every page already has its own h1 (an entry's word, a book's title, Settings; the
  journal editor's is visually hidden, "Entry" / "New entry"), and the e2e test now checks exactly one h1 on the
  phone pages it visits — cost if wrong: a page without an h1 would show only in the test, which then fails.
- Ruling: `setFrameTitle` and `phoneTitle` stay — drawer mode still shows the title (owner: unchanged there) —
  cost if wrong: none.
- Ruling: the empty space where the title was stays flexible (the logo is followed by a spacer), so the page
  actions, the workspace flag and the avatar stay on the right — cost if wrong: none.
