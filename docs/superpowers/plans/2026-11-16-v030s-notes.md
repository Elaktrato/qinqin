## Global constraints

- Plugin id `qinqin-core` (`CORE_PLUGIN_ID`, Go `backup.CorePlugin`); keys `note:<entryId>` (decimal,
  positive, no leading zero, no sign) and `notecfg`; always with `?workspace=<current>`.
- Note absent unless: live row, object, `version === 1`, `entryId` positive integer equal to the key's
  number, `text` a string non-empty after trimming. `notecfg` absent/unreadable → `onAnswer: true`.
- Cap `NOTE_MAX_CHARS = 2000` code points (`Array.from(text).length`) after normalising (`\r\n`/`\r` →
  `\n`, trailing whitespace of the whole text trimmed). Empty after normalising = delete.
- Unknown data members are kept verbatim on save (note and `notecfg`).
- Rendering: text interpolation only, `white-space: pre-wrap; overflow-wrap: anywhere`; NEVER `{@html}`.
- Answer box only when the card is revealed; one notes list request per session; a failure shows no
  notes and never blocks; offline sessions show none.

## Review Focus

1. **XSS:** no `{@html}`, no `innerHTML`, no autolinking in `lib/notes/**`, the entry page and the session
   page; DOM tests render `<img src=x onerror=alert(1)>`, `<script>` and `javascript:` text literally
   (Tasks 6, 7, 9).
2. **User and workspace isolation:** user B cannot GET/PUT/DELETE/list A's `note:*` (404, A's row
   unchanged); A's note in workspace 1 is not listed in workspace 2; the backup exports only the caller's
   live notes (Tasks 5, 3).
3. **Restore correctness:** a note follows its entry to a server with other entry ids; unresolved → dropped
   and reported; two notes on one target → newest wins, no blocking; non-note rows and `qinqin-flashcards`
   rows byte-identical to before (Tasks 2, 3, 4).
4. **No regression:** `remap.json`'s existing cases unchanged; study data still ignores `qinqin-core` rows;
   sessions without notes look exactly as before (Tasks 2, 7).
5. **Answer never leaks early:** the note box is absent before reveal for every kind (Task 7).
