## 3. Rulings worth knowing (full text in each plan)

- **Rate limiting:** four layers; `QINQIN_TRUSTED_PROXIES=none` is recommended without a reverse
  proxy; the hash gate answers 503 `busy` under load (a flaky CI test was fixed, `58b42fd`).
- **Sessions:** stored hashed, 90-day idle expiry, restricted sessions (`password_change`,
  `mfa_enrollment`), forced password change revokes all sessions.
- **Admin destructive actions need the acting admin's current password** (delete a user, issue a
  reset link, grant admin, MFA reset of another user, server backup; plus the authenticator code
  when the admin has one).
  *Note 2026-11-16 (v0.4.0 prep, #91):* this claim was wrong in v0.3.0. Only the server backup asked
  for the authenticator code; creating a user with `admin: true` asked for nothing at all, so a stolen
  admin session alone could mint an administrator. Fixed in the v0.4.0 prep: every destructive admin
  action (including creating an administrator) goes through one re-authentication helper.
  A second review pass the same day found more: admin address changes (also one's own, which led to
  a full takeover through a reset link), the mail settings (redirecting reset links via the public
  URL), demoting or disabling another admin and lowering Security settings had no re-authentication.
  All now do; the exact list is in `docs/contracts/auth/README.md`, Administration.
- **Pending reset links die with every containment action** (password change, forced change,
  disable, revoke-all, `qinqin recover`, address change).
- **MFA:** TOTP SHA-1/6/30 s ±1, replay-protected, secrets sealed with `QINQIN_SECRET` and bound to
  the user id; recovery codes hashed; second-step challenges remember their first factor and the
  methods issued, so the email second step is never offered after an emailed code or a reset
  (mailbox alone cannot beat an authenticator). Users whose ONLY second step is email are
  mailbox-only by construction (documented). Email-only users fail closed when mail is down.
- **Email addresses:** IDNA-normalised, non-ASCII local parts rejected (SMTPUTF8 unsupported).
- **Daily limits are per deck;** reverse/cloze cards count as new; the home widget and decks view
  show "left today".
- **Vacation:** whole-day shifts of the study clock; reviews during a vacation are fed at the
  frozen instant; the optimizer uses study time.
- **Backup:** restore is one transaction under a server-wide single restore lock (blocks other
  writes about 30 s per million events), at most 2,000,000 events per restore; exports are refused
  when this server would refuse to restore them; safety exports keep the last three.
- **PWA:** no Workbox; exact allowlist of cacheable GETs (admin, account, backup, ticket routes
  bypass the worker); cache partition = hash of the request's credential; outbox bound to
  `(user, token)`; a mismatch always means keep.

## 4. Review findings that were fixed before merge (for confidence)

Legacy plaintext session tokens left in the DB file after migration; username uniqueness; pending
reset links surviving recovery; email-existence probing without a password; three MFA bypasses
(mailbox-only sign-in, reset-by-mail plus email code, enrolment self-promotion); deck sessions
exceeding daily limits through unfiltered counts; wrong furigana for inflected 来る; restore stalling
the whole server and exports that could not be restored; server backup without the authenticator
code; a stale tab replaying one user's reviews with another user's token; offline "prepared" claims
for an empty cache.
