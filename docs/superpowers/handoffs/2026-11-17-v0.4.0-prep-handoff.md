### Item 5 in short
- The server builds versioned, checksummed packages (`lexicon.<lang>`, `levels.*`, `sentences.*`, `frequency.*`,
  `components.*`, `audio.*`, `grammar.*`, `strokes.*`) as zip files holding a SQLite database, licence texts and
  a manifest; `GET /api/packages` (catalogue, ETag) and `GET /api/packages/{id}/{revision}` (Range, 2 concurrent
  downloads per user, `download_busy`). Build is in a single goroutine, memory is O(batch), `<data>/packages`
  is derived and not backed up. A cross-process lock protects `qinqin seed` against a running `serve`.
- `GET /api/sync/pull?v=2` pages the user's own data (keyset by `(updated_at, rowid)`, a round fixes `until`,
  cursor lags 30 s, 500 rows / 4 MiB per page, `tombstones=1` for from-scratch rounds, language filter, `scope`
  and `restarted`). The legacy form (old shells, token scripts) is streamed and no longer carries the lexicon
  (`sync_collection_moved`).
- Stroke data is an installable pack (`hanzi-writer-strokes`, Arphic Public License, built by
  `scripts/prepare-strokes-pack.mjs` from the pinned `hanzi-writer-data` npm package), served by Go at the same `/hanzi/U<HEX>.json`
  URL, auto-installed at startup when none is installed.
- Measured on a fully seeded server: full legacy pull 260 MB / peak RSS 1.46 GB before, 0.55 MB / +0.5 MB after;
  Go binary 65 MB → 32 MB; web build 35 MB → 2.7 MB; first package build of everything ≈ 34 s; v2 full round
  (45 pages) ≈ 4.7 MB.

## 3. Rulings worth knowing (full text in each spec/plan)

- Packages are per language for dictionaries (`lexicon.<lang>`), contain only what is installed, carry licence
  texts, are read-only on the client (file swap, never merged). Catalogue and downloads need a signed-in user
  (read tokens allowed). Download caching is `private, no-cache` + ETag (revisions can be reused after a server
  restore). `download_busy` is its own code (retry allowed, unlike `rate_limited`).
- Pull v2 pages are keyset windows bounded by `until`; the cursor and page tokens are opaque and bind user and
  filters; `lookup` events never ship; `tombstones=1` exists so the web (which always pulls from scratch) keeps
  tombstones for its LWW stamps. A from-scratch round started in the same second as a write may omit that row
  until the next load (rows stamped in the round's own second go to the next round). Review rows lost mid-round
  are repaired by the next load.
- Event `ts` is stored as UTC whole seconds (the old "kept verbatim" comments were wrong and are fixed);
  same-second order is by id; Android should send whole-second UTC.
- Milestone seen-state is plugin-data rows, not a typed table (no migration); the dismiss is bound to the
  workspace the card was computed for.
- i18n: in-house format (no library); API `message` stays English and clients show text by `code`; English
  formats as `en-GB`; uncoded plain-text server refusals are shown as written; interface text carries no `lang`
  of its own (study text gets the study language).
