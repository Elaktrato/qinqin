# #347 — a real written form outranks a search-only one in word resolution (2026-11-28)

Issue: "dictionary: 虹 (にじ) resolves to 二次 because a search-only form outranks the real entry". Branch
`feature/v090-347-resolver` from `feature/v090-346-sense-order`.

## What

The word resolver (`lexicon.Store.Best`, `BestWord`, `BestWordReading`: level packs, frequency starter decks, the
Starter sets, sentence packs) picks among the entries that have a written form by priority. JMdict 二次 (j:1461870,
priority 95 from nf06) lists 虹 as a search-only form (`sK`) and reads にじ, so it beat the real 虹 (j:1463740, nf17).
Rule: an entry where the form is a written form that is **not** search-only comes first, whatever the priorities;
the priority order applies after it. An entry that has the form only as search-only still resolves when nothing else
has it.

## Rulings

- Ruling: only `sK` (search-only) loses the tie-break, not `rK`/`iK`/`oK` — the issue is about search-only forms,
  which the display rule already never shows; a rare or irregular form is still a written form (為る is rK and is
  the right entry for する) — cost if wrong: a rare-form homograph could still win by priority; extend the flag list.
- Ruling: the sK check sits **before** the usually-kana and priority keys and after the character-headword key of
  `Best` (a character entry headed by the form) — the issue says "whatever the priority tags" — cost if wrong: none
  known; characters never carry sK.
- Ruling: the kana fallback (`bestKanaWordQuery`) and `KanaOnlyWordID` are unchanged: they match readings, where a
  search-only kana reading (`sk`) already is not a word's first reading in practice.
- Ruling: no data migration — resolution happens at import (levels, sentences) and at request time (starter decks,
  Starter sets); an installed level list keeps the entry it resolved until `qinqin seed` re-imports it (release note).
