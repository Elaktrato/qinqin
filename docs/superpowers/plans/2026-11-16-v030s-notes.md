## Global constraints

- Plugin id `qinqin-core` (`CORE_PLUGIN_ID`, Go `backup.CorePlugin`); keys `note:<entryId>` (decimal,
  positive, no leading zero, no sign) and `notecfg`; always with `?workspace=<current>`.
- Note absent unless: live row, object, `version === 1`, `entryId` positive integer equal to the key's
  number, `text` a string non-empty after trimming. `notecfg` absent/unreadable → `onAnswer: true`.
- Cap `NOTE_MAX_CHARS = 2000` code points (`Array.from(text).length`) after normalising (`\r\n`/`\r` →
  `\n`, trailing whitespace of the whole text trimmed). Empty after normalising = delete.
- Unknown data members are kept verbatim on save (note and `notecfg`).
- Rendering: text interpolation only, `white-space: pre-wrap; overflow-wrap: anywhere`; NEVER `{@html}`.
- Answer box only when the card is revealed; one notes list request per session; a failure shows no
  notes and never blocks; offline sessions show none.

### Deviations and rulings made while building

- Ruling: two archive notes can NOT actually land on one target entry today — `resolveEntries` maps at
  most one archive entry to a target entry (two written-form matches onto one target are both
  unresolved; exact beats written-form). The spec's premise ("possible through the written-form
  fallback") is wrong. The newest-wins rule is still implemented and unit-tested
  (`TestNoteCollisionNewestWins`, per-workspace, order-independent) and wired into Plan and Restore —
  defensive, cheap — cost if wrong: none. The plan's integration test "two notes on one target → no
  Blocking" was therefore not built (cannot be constructed through `Plan`); the backup README says so.
- Ruling: the tie-break "smaller source key" is implemented as the smaller source entry id (numeric),
  not string order of the key — natural for ids, written in `backup/README.md` and `notes/README.md`
  — cost if wrong: only the winner of an exact-time tie in a case that cannot happen today.
- Ruling: `parseNote` decodes a string holding JSON text of an object (as the web SDK does) — fixture
  case — cost: none.
- Ruling: "whitespace" for trimming is JavaScript `trim`/`trimEnd` (Unicode White_Space, so U+3000);
  written in the contract with a fixture case, so Android must match it.
- `loadNote` reads through the prefix route (`?prefix=note:<id>`, exact key picked) instead of
  `GET .../data/note:<id>`, so a word without a note logs no 404; PUT and DELETE use the key route.
  `saveNote` returns `Note | null` (null = the save was a delete) instead of `Note`.
- Tests of Tasks 4 and 5 live in a new `server/internal/backup/notes_test.go` instead of
