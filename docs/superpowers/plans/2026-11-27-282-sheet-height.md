# #282 — the phone lookup sheet takes at most 50–60 % of the screen (2026-11-27)

Milestone v0.9.0, phase 1 (foundations and bugs). Branch `feature/v090-282-sheet-height`.

## What

On a phone the reader's lookup sheet (`lib/features/reader/LookupSheet.svelte`) can grow almost to the top of the
screen and cover the text being read: it inherits the shared `lib/ui/Sheet.svelte`'s `max-height: 85dvh`. Cap the
lookup sheet at 55 % of the screen; its content (entries, actions, the highlight bar) scrolls inside the sheet.
The other sheets (More, the reader rail, the journal's corrections, the study modal) keep 85 %.

The tap-to-look-up work already measures the sheet: `LookupSheet` sets `--lookup-sheet-space` (the page's room
under its end) and calls `keepWordAbove(innerHeight - dialog.offsetHeight)` on open, on a resize of the sheet and
of the viewport. Both follow the measured height, so they follow the cap; the tests check it.

## Rulings

- Ruling: 55dvh — the middle of the owner's 50–60 %; on a 740 px phone that is 407 px, room for the word line,
  the first entry's headword and two or three glosses, with the text above still readable — cost if wrong: a
  one-line change of the constant.
- Ruling: a `maxHeight` prop on `Sheet` that sets a custom property (`--sheet-max-height`), not an inline
  `max-height` and not a global change — the issue asks for a prop or a class; a custom property keeps the default
  in the stylesheet and lets a test read the cap of one sheet — cost if wrong: none.
- Ruling: `dvh`, as the default cap — the dynamic viewport shrinks with the on-screen keyboard and the browser's
  bars, so the sheet never covers more than 55 % of what is visible — cost if wrong: on a browser without `dvh`
  the whole declaration is dropped and the sheet has no cap (no supported browser lacks it: Chrome 108+, the
  Android WebView follows Chrome).
- Ruling: the e2e test asserts ≤ 60 % (the issue's upper bound), not exactly 55 % — the test checks the owner's
  requirement; the exact value is the CSS constant, which the DOM test pins — cost if wrong: none.
- Ruling: no new sheet-only drag behaviour — dragging up was already a no-op (`dragY = max(0, dy)`), so the cap
  holds while dragging; a test pins it — cost if wrong: none.
- Ruling: the long entry is a new word in the e2e fixture pack (辞書, CC0 like the rest of it) instead of a
  mocked lookup answer — the lookup is the flow under test and the word is used by no other spec — cost if wrong:
  a future spec that counts the fixture's entries counts one more.
