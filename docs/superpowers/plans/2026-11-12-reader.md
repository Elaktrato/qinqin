# Reader Plugin & Core Tokenizer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a core zh/ja longest-match tokenizer, a generic plugin page mechanism, and a webview reader plugin with hover/selection dictionary lookup, one-click imports from Aozora Bunko and Project Gutenberg, and epub upload.

**Architecture:** The tokenizer is a core Go service over the existing dictionary tables, with Japanese deinflection in the `ja` language pack, exposed as public JSON endpoints. Plugins gain a `page` surface: a manifest lists pages, one generic SPA route renders the owning plugin's component, and the shell nav lists them. Books are core generic data: metadata in a new SQLite table, normalized chapter content as JSON files under the data dir, filled by an epub parser and two source adapters; the reader plugin only consumes the `/api/library/*` and `/api/segment*` endpoints.

**Tech Stack:** Go 1.26 stdlib `net/http` + `modernc.org/sqlite` (+ `golang.org/x/net/html` for XHTML), SvelteKit 2 / Svelte 5 + vitest, `opencc-js` (client-side zh variant conversion).

**Spec:** `docs/superpowers/specs/2026-11-12-reader-design.md`

## Global Constraints

- Backend is pure Go, no CGO; routes are `mux.HandleFunc("METHOD /path", ...)` in `server/internal/api/api.go`; handlers are methods on `*server`.
- Tokenizer is core and shared; the reader must not implement its own segmentation. Flashcards Round 3 waits for it; Round 2 is untouched.
- Plugin backends stay thin: the reader registers a manifest (`qinqin-reader`) only. Library, import and epub logic are core generic code.
- Offsets in the segment API are **Unicode code points** (runes), never bytes or UTF-16 units.
- Book content is not stored in `plugin_data`; next migration number is `012`.
- Imports are user-triggered, one book at a time; only catalog indexes may be downloaded in bulk. Every outbound request sends a descriptive `User-Agent` (`qinqin/<version> (+https://github.com/Elaktrato/qinqin)`) and is cached and rate limited.
- Only Aozora works whose catalog copyright flags mark them free of copyright are listed or importable. Wikisource is out of v1. "Add to study" is out of v1.
- Epub upload cap: 20 MB. Rendering is text, paragraphs and ruby only; no images, no vertical layout.
- Japanese deinflection v1 covers: polite, past, negative, te-form, potential, passive/causative, volitional, conditional for verbs and i-adjectives.
- Webview only; hover is mouse-only, selection lookup should also work on touch.
- Gates before each commit batch: `cd server && go vet ./... && go test ./...`, `npm --prefix apps/web run check`, `npm --prefix apps/web test`.
- Git flow: work on `feature/reader` cut from `develop` (`docs/git-flow.md`). Commit per task.

## Review Focus

- Astral-plane characters (e.g. `𠮷`, UTF-16 surrogate pairs) in a paragraph: hover must resolve the right word because the browser offset is UTF-16 and the API offset is code points (Task 1, Task 12).
- Cursor over punctuation, whitespace, Latin text or digits: no popup and no error (Task 1, Task 12).
- Malformed, truncated, zip-bomb or spine-less epub: clean 4xx/422, nothing stored (Task 6).
- Aozora text quirks: Shift_JIS decoding, gaiji notes `※［＃…］`, `｜漢字《かな》` ruby, 底本 footer, and works missing from the free-of-copyright filter (Task 7).
- Source down/slow, or the same book imported twice: bounded timeout, clear error, no partial book, no duplicate row (Task 8).

  ```go
  type Candidate struct{ ID int64; Kind string } // "character" | "word"
  type Match struct {

  func (s Service) Segment(ctx context.Context, language, text string) ([]Match, error)

  ```
