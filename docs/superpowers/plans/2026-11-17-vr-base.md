## Global constraints

- Tokens only: no hex/rgb/hsl literal and no `prefers-color-scheme` in any new `lib/ui` file (PART B's lint
  enforces it repo-wide; PART A's own test enforces it for `lib/ui/` from Task A1 on).
- Every string through the catalogue (`t()` / `<Msg>`); new keys in `en.json` (sorted), used literally in
  non-test `src/`. Components that need a visible word take it as a prop (the caller passes `t(...)`); the
  components' own words are `common.*` keys.
- Accessibility: every interactive component is reachable and operable by keyboard, has a visible
  `:focus-visible` ring (`--focus-ring`), works in forced colours (system colours, borders where fills
  disappear), and every animation uses the motion tokens (zero under `prefers-reduced-motion`). Icon-only
  buttons always have an accessible name and a tooltip on hover and focus (IconButton requires `label`).
- §5: a box needs a reason; separators are `--hair` 1px; type tops out at 600; labels sentence case, ~12.5px,
  no all-caps; one primary action per view in the soft accent tint; fields are an underline; tabs a 2px accent
  underline; never colour alone.
- Licence first: the icon set's licence text is fetched from the package and read before anything is
  committed (done, below); copied verbatim; credited.

## Rulings

- Ruling: the icon set is Lucide (vendored path data), not our own drawings — it is a consistent, well-drawn
  line set on the 24 grid that already meets §5 at stroke 1.5, its licence (ISC + MIT) is clear and verified,
  and it does not look like stock Material — cost if wrong: one licence notice to carry; swapping sets means
  regenerating `lucide.ts` (the `IconName` list is the only API).
- Ruling: vendored as data by a script (`apps/web/scripts/vendor-icons.mjs <package-dir>`), not an npm
  dependency — only the ~40 icons we use ship, and nothing new enters `package.json` — cost: adding an icon
  means rerunning the script against a downloaded package (documented in the script header).
- Ruling: `NavIcon.svelte` stays (same props) and draws Lucide icons through `Icon` — the shell keeps working
  and changes look in one place; the frame rework (#99) replaces NavIcon with `Icon` — cost: two icon
  components exist until #99.
- Ruling: the showcase is a vitest project (`gallery`), not a route — a `/dev/ui` route would ship in the
  embedded build (adapter-static emits every route's chunk) even behind a dev guard; the test renders every
  component in jsdom with real CSS and can write a static HTML file for Playwright — cost: the gallery is
  static (no hover); interactive states (open menu, tooltip, sheet) are rendered open by props.
- Ruling: Tooltip is our own element (`role="tooltip"`, shown on hover and on keyboard focus, hidden by
  Escape, stays while hovered) — `title` is not shown on focus or touch and cannot be styled — cost: a few
  lines of JS per tooltip.
- Ruling: Dialog and Sheet are built on the native `<dialog>` with `showModal()` (the browser makes the rest of
  the page inert, traps focus, handles Escape through `cancel`) plus a script fallback for environments without
  `showModal` (jsdom; old WebViews): `open` attribute, Tab wraps inside, Escape closes — cost: none known.
- Ruling: the six existing dialogs (`LogoutDialog`, `DeleteAccountDialog`, `DeleteUserDialog`,
  `DeleteWorkspaceDialog`, `CreateTokenDialog`, `ResetMfaDialog`) share `Dialog` — they repeat the same
  showModal/cancel/focus code — and move onto it in PART B (Task B6), not now, so PART A changes no page —
  cost: they look different until B6.
- Ruling: the primary button's text is `--reading-accent` (the accent where it reaches 4.5:1 on `panel`, else
  `text`) on `--primary-wash` — accent-coloured small text must stay readable (design §7) — cost: in a theme
  whose accent is weak, the primary button reads as tinted text-coloured.
- Ruling: Button also has `variant="filled"` (accent fill, `--on-accent` text) for the few places a filled
  accent is the only cue (the sign-in submit today) — the on-accent rule exists for exactly this — cost: it can
  be overused; the README says "rare".
- Ruling: Menu is `Menu` (the trigger button and the popup) plus `MenuItem` children (a button, a checked
  radio item, or a link), with ThemeSwitch's behaviour (roving focus, Arrow/Home/End, Escape returns focus, Tab
  and outside click close) moved into Menu and ThemeSwitch rebuilt on it — one implementation — cost: the
  ThemeSwitch tests are the regression net (kept unchanged).
- Ruling: Tabs has two forms: in-page tabs (`role="tablist"`, automatic activation, roving tabindex) and route
  tabs (`<nav>` with links and `aria-current="page"`, for Stats' Overview/Characters/Week which are routes) —
  the APG says links that navigate are not tabs — cost: none.
- Ruling: Chip carries meaning by text, never by colour alone: `tone="good"` adds a small `good` dot (shape) in
  front of the text, the text stays `--text`; no border, a `--raised` wash, radius `--radius` — §5 forbids
  bordered pills — cost: none.
- Ruling: Section is unboxed (a small sentence-case heading and a `--hair` separator above the next Section);
  Panel is the only box and its doc names the allowed reasons (content surface, menus/sheets, selected rows) —
  "a box needs a reason" becomes a component choice — cost: none.
- Ruling: motion tokens (`--motion-fast` 120ms, `--motion-medium` 200ms, `--ease-standard`) become `0ms` under
  `prefers-reduced-motion: reduce` in `app.css`, so every component that uses them complies without its own
  media query — cost: a component using a literal duration escapes it (PART B's lint can grow a rule).
- Ruling: the focus ring is `--focus-ring: 2px solid var(--accent)` with `--focus-ring-offset: 2px`, and
  `Highlight` in forced colours — the accent is the "current place" colour (§5) and every offered accent is at
  least 3:1 on `panel` (the WCAG minimum for focus indicators) — cost: a theme whose default accent fails 3:1
  (reported at install) has a weak ring.
- Ruling (PART B): the colour lint runs with a ratcheting baseline (like the i18n `pending` baseline): a file
  in the baseline may still hold literals, a clean file in the baseline fails the test (remove it), a new
  offender fails — the migration lands in batches while the rule holds from the first commit — cost: none.
