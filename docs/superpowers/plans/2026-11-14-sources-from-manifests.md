# Sources page built from pack and plugin manifests (issue #49)

**Goal:** The Sources page (`/sources`) and `docs/sources.md` stop being hand-maintained markup. A pack or plugin that brings third-party material declares it once, in its manifest, and the page picks it up. Closes [#49](https://github.com/Elaktrato/qinqin/issues/49).

**Owner request (2026-11-14):** "work on the github issue regarding the sources", partly built from the plugins and what they list as their sources. Design decisions below were made by the assistant from the issue text; the owner can overrule them in review.

## Today (facts from the code)

- `GET /api/dictionaries`, `/api/frequency-packs`, `/api/schemes` serve `license` and `attribution` from pack `manifest.json` (Go `dict.Manifest`; tables `dictionaries`, `frequency_packs`, level `schemes`, columns `license TEXT NOT NULL`, `attribution TEXT NOT NULL` from migrations 005/007/015).
- The long caveats are hard-coded in `apps/web/src/routes/sources/+page.svelte`, shown when a pack id is installed (JLPT, HSK, frequency, Aozora/Gutenberg-style credits, stroke data, opencc-js).
- Web feature plugins declare `PluginManifest {id, name, version?, surfaces}` in `apps/web/src/lib/plugins/<name>/manifest.ts`, listed in `apps/web/src/lib/plugins/index.ts` (`webPlugins`). The reader and flashcards plugins list no sources.
- CI: `.github/workflows/build.yml`.

## Design (rulings)

1. **Pack `notice`.** `dict.Manifest` gets an optional `notice` string (plain text; paragraphs separated by a blank line; links written as `[text](https://…)` only; no other markup). Stored in a new column `notice TEXT NOT NULL DEFAULT ''` on `dictionaries`, `frequency_packs` and level `schemes` (migration 024, additive, no rebuild), imported with the pack, served as `notice` in the three API responses, updated on re-seed when changed (an identical re-import must not restamp rows: follow the existing no-restamp rule). Validation: ≤ 4,000 bytes, links must be `https://`.
2. **Safe rendering.** A pure web module parses a notice into nodes (`paragraph → [text | link]`) and the page renders them with Svelte elements: never `{@html}`. Unknown or malformed link syntax renders as plain text.
3. **Plugin sources.** `PluginManifest` gains optional `sources: SourceCredit[]` where `SourceCredit = {name, url?, license?, attribution?, notice?}` (same `notice` mini-markup). The Sources page gets a "Plugins" section built from `webPlugins` manifests: for each plugin that declares sources, show the plugin name and its credits. The reader declares Aozora Bunko, Project Gutenberg (as fetched sources) and opencc-js; flashcards declares nothing unless it ships third-party material (check: hanzi-writer is used by flashcards writing cards and the entry stroke player: declare hanzi-writer and the stroke-order data under core credits, see 4). The server plugin registry is NOT extended (web manifests are compile-time and are the plugin's own declaration).
4. **Core credits as data.** The hard-coded static credits that belong to the app itself (stroke-order data `hanzi-writer-data`/Arphic Public License with its shipped licence text link, `hanzi-writer`, `opencc-js` if used by core rather than the reader (it is used by the reader: declare it there), `ts-fsrs`, licence texts shipped under `apps/web/static`) move into one typed module `apps/web/src/lib/sources/coreCredits.ts` (same `SourceCredit` shape) rendered in a "Built into the app" section.
5. **No hard-coded per-pack notice remains in the page.** The conditional notices (frequency list, JLPT kanji approximate, HSK terms, the old local hsk30/jlpt-words notes) become the `notice` of the respective pack manifests. Committed packs get their manifests updated through their generators (`scripts/prepare-level-packs.mjs`, `scripts/prepare-hsk-syllabus.mjs`; `levels.json` must stay byte-identical, only manifest/ATTRIBUTION text may change) or by hand for hand-maintained packs (`plugins/data/jiten-frequency`, dictionaries). Locally generated optional packs (JLPT vocabulary via `--jlpt-vocab`, ivankra `--hsk`) emit a `notice` too so they show up with their caveat. A notice shown for a pack that is not installed no longer exists by construction.
6. **Docs consistency check.** `scripts/check-sources.mjs` (+ test): fails when a pack directory under `plugins/data` or `plugins/samples` lacks a manifest `license`/`attribution`, when a bundled pack id (`plugins/data/*`) is not mentioned in `docs/sources.md`, or when `docs/sources.md` names a bundled pack id that does not exist. Run it in `.github/workflows/build.yml` (a cheap step before the build) and document it. `docs/sources.md` is NOT generated; its table intro says the Sources page is the live source of truth and links to it.
7. Honest wording rules stay (licence status as the publisher states it; unverified facts marked unverified; nothing claimed that upstream does not say). Keep every existing licence statement's CONTENT; only its location moves.

## Tasks

**T1 server** — migration 024 (`notice` columns), `dict.Manifest.Notice` + validation (+ tests), importers/registry writes (dictionaries, frequency packs, levels schemes), API fields in `model` structs and handlers (`notice` omitted? no: always present, empty string when none), no-restamp on identical re-import, update on changed notice, tests incl. migration on a populated DB, re-seed changes notice, API JSON. Pack manifests: add `notice` to every committed pack that needs a caveat (move the text out of the Sources page: frequency/jiten, jlpt-kanji, hsk-words, hsk-chars; regenerate through the generators for the three level packs; check the manifest validation and `go test ./cmd/qinqin` bundled-pack tests). Gates: Go in Docker + `-race ./internal/dict ./internal/levels ./internal/api ./internal/db ./cmd/qinqin`.
**T2 web** — `lib/sources/notice.ts` (parser, tests incl. malformed links, `javascript:`/non-https links stay plain text, long text), `lib/sources/credits.ts` types, `lib/sources/coreCredits.ts`, `PluginManifest.sources` + reader/flashcards manifests, the Sources page rebuilt from API data + `webPlugins` + core credits (tables unchanged in look; notices rendered under each row or in a "Notes" block per section; "Plugins" and "Built into the app" sections), types in `lib/api/types.ts` (`notice?: string`), remove every hard-coded per-pack notice and the `installedPacks` conditional machinery; a11y (headings, table scope, `lang` attributes for CJK text), tests, README/docs mentions. Gates: web check/test/build. Real-app check: seed a scratch data dir, open `/sources` in headless Chromium: all bundled packs show their notice, a plugin section lists the reader's sources, no console errors, 390 px and dark mode screenshots read.
**T3 docs + CI** — `scripts/check-sources.mjs` + test, CI step, `docs/sources.md` (restructure per ruling 6: short intro pointing to the live page, per-language tables stay as the human overview), README + `plugins/data/README.md` (manifest `notice` field documented with the mini-markup and limits; plugin `sources` documented in the plugin docs: find where the plugin manifest is documented and add it). Gates: node tests, check script passes on the repo.
**T4 review** — independent read-only review (authz not relevant: all public; focus: XSS/link safety, migration safety on a copy of a populated DB, no-restamp rule, API compat, content preserved (diff the old hard-coded notices against the new manifest notices: nothing dropped or altered in meaning), docs honesty), then one fix wave.
