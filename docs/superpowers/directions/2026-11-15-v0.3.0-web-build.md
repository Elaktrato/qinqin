## Rules (same as the previous run)

- Decide alone. Licensing first, then best UX, even at higher development cost. Unclear or
  restrictive licences stay local, gitignored, never bundled.
- Every work item: spec (if none exists), plan (writing-plans), then execute **subagent-driven**:
  a fresh implementer per task, an independent review on the strongest model, one fix wave per
  branch, a whole-branch review at the end.
- No local browser automation (Playwright etc.). Use jsdom component tests, curl and built-server
  checks. Go is not installed locally: run Go gates in Docker as the normal user.

  handoff, not into a question.

## Work items, in this order

Each item has an issue; update the issue (comment + close when done) and `docs/ROADMAP.md`.

### 1. Small fixes
- **#86** login/register rate limiting and lockout (each failed login costs a 64 MiB argon2 run).
- **#84** heatmap and activity days in the learner's local time zone. This defines "the learner's
  day" for everything below; document the rule (where the zone is stored, how events are
  bucketed, DST) in the contract (item 9).
- **#57** level sessions for character-unit schemes (JLPT kanji, Jōyō grades, 通用规范汉字表).

### 2. Account basics — #64 (read its comments; the owner's decisions are authoritative)
- **Registration is closed by default.** (Today: first user becomes admin, then admin-only. Keep
  the first-user bootstrap.) The admin can enable **invite links** (limited uses, optional
  expiry) and optionally open registration.
- **Admin creates a user** with username and password; that user is **forced to set a new
  password at first login**. Admin can also issue **password-reset links**.
- **Email policy set by the admin:** off / optional / required. Required means mandatory at
  registration and for admin-created accounts.
- **SMTP is optional and lives in core** (not in a plugin). **Only the admin can view or edit it**, in admin settings on the server; the password is stored encrypted (like AI keys, `QINQIN_SECRET`), and is never logged or returned by the API (show only that one is set). Include a "send test mail" action.
  With SMTP: password reset by mail for users who have an email; the admin may **enforce MFA** for
  all users; the admin may enable **passwordless login by emailed one-time code** instead of a
  password. Without SMTP these features are hidden, not broken. Rulings yours: MFA method
  (suggestion: TOTP with recovery codes; email OTP as an alternative), OTP length/expiry/rate
  limits, token hashing, enumeration-safe responses, constant-time checks.
- Change password, session list/revoke/"log out everywhere", user management (list, disable,
  delete with a clear statement of what is removed, promote/demote; the last admin cannot be
  removed or demoted), delete my own account and data.
- Fold in the #1 leftovers (bootstrap race, login timing). Authorization tests on every admin
  route and the last-admin rules. Never log passwords, tokens or OTPs.

### 3. Reverse and cloze cards — #65
- Reverse (meaning → word): words only. Cloze: built from the example sentences linked to an
  entry. Both **opt-in per deck**; existing decks are not changed.
- Sibling cards of the same word are **buried until the next day** after one is answered.
- Review history stays event-sourced; card ids stay deterministic and duplicate-proof across
  devices. Card-type opt-out and card management (#30) must work with the new types.

### 4. Vacation mode — #88 (the owner's final design)
- Dated periods in plugin data; the scheduler excludes vacation days when measuring time since
  the last review. Nothing is rewritten; ending early is trivial.
- During a vacation: nothing due, no new cards, study page says "Vacation until …". After it,
  no backlog avalanche.
- **Scope: all workspaces, or a checklist of chosen workspaces** (both options in the UI).
- Streaks: vacation days are neutral (do not extend or break). Heatmap/stats mark them; check
  the core stats service (#48) and the Stats pages.
- **Uses the learner's local day (item 1, #84).** No periods in the past; overlapping periods
  merge; start now or scheduled; end early.
- The FSRS optimizer and due counts must handle vacation days consistently.

### 5. Backup — #61
- Per-user export: a zip of JSON (events, plugin data, workspaces, overlays; not dictionaries,
  not AI keys, not secrets). **Restore replaces all of the user's data** (with a clear confirm
  and a pre-restore safety export offered). Versioned format; reject unknown versions.
- Admin-only whole-server backup (a consistent SQLite copy, e.g. `VACUUM INTO`) with documented
  restore steps.

### 6. PWA — #79
- Installable; caches the app shell and the day's due cards; queues reviews offline and syncs
  them on reconnect through the existing event sync (idempotent ids). Never cache another user's
  data across a logout. Update flow for new versions.
- Hand-check items (install prompt, iOS) go in the handoff.

### 7. Contracts for the Android client
- Write `docs/contracts/` describing the shared rules the Kotlin app must reproduce: scheduler
  and due counts (incl. vacation and the learner's day), streaks, cloze/reverse card ids and
  generation, sync/event formats, auth and session flow. Each rule with JSON fixtures that both
  the TypeScript and (later) Kotlin code can run, like `apps/web/src/lib/writing/fixtures/`.
- Cover the Android notes in the previous handoff: the client must read `fsrs:*` plugin rows;
  `GET /api/languages` rows can have `installed: false`; `GET /api/plugins` has `hidden`.
