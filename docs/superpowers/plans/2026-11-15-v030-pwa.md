## Global constraints

- The worker never reads or writes `localStorage`, never caches a request without `Authorization`
  in an API partition, never caches non-GET, never stores a non-200, and never touches a path outside
  the allowlist (`classify` is the single gate; tests iterate the route table of `api.go` — copied
  into a fixture by Task 7 — and assert every `/api/admin/*`, `/api/account/*` and auth route except
  `me` is `bypass`).
- No automatic `skipWaiting`. No Background Sync. No Workbox.
- Request URLs that are cached are built by the same exported helpers the pages use
  (`SYNC_PULL_PATH`, `fullLogPath`, `entryPath`), so prefetch and page agree byte for byte.
- Components thin; logic in tested pure modules; jsdom tests use `src/lib/testing/domSetup.ts`
  (Node 26 CI); worker tests run in the node project with `src/lib/testing/fakeCaches.ts`.

## Rulings (plan-specific)

- Ruling: `kit.version.name` = `process.env.QINQIN_BUILD_ID` or the output of `git rev-parse --short HEAD`
  (try/catch) or `String(Date.now())` — deterministic per commit where git exists, unique otherwise;
  the Dockerfile passes nothing new (the git fallback works in the build stage only if `.git` is
  copied; otherwise the timestamp is fine: every build is a new version) — cost if wrong: an
  identical rebuild shows an update banner once.
- Ruling: `kit.serviceWorker.files` excludes `hanzi/` and the licence `.TXT` files from the `files`
  list (they would be 9 000+ precache entries) — the worker recognises `/hanzi/` by path — cost if
  wrong: none.
- Ruling: the hanzi cache is capped at 4 000 entries by deleting the oldest keys in insertion order
  (`cache.keys()` order) after each put — no LRU bookkeeping in IndexedDB — cost if wrong: a frequently
  used character may be evicted and refetched.

1. **Cross-user leakage:** partition = hash of `Authorization`; no cache use without it; cleanup on
   sign-in/sign-out/401; outbox per user; a second user on the device sees nothing (Tasks 4, 6, 8).

   bypass; `sync/pull` only with plugin collections (Task 7).

   unchanged; offline sessions never write plugin data.
4. **Update safety:** no automatic `skipWaiting`; one reload; old shells deleted only on activate.
5. **#20 caching rules intact:** `index.html` no-store, immutable assets unchanged, worker no-cache.
