# #288 + #289 — honest study counts, only card types that have cards (2026-11-27)

Milestone v0.9.0, phase 1 (plan §5: "planning-time eligibility, honest counts, hide empty card types"). One branch,
`feature/v090-288-honest-counts`. Neither issue has an owner-decision comment; the issue bodies and the v0.9.0 plan
are the brief.

## What

- **#288.** A Japanese deck with Word Salad or Cloze selected: the modal said 20, the session went 0/20 → 0/1 → "no
  cards". Companions (sentence, tone, reverse, cloze) are planned for every vocab card and checked only when shown
  (`cardFlow.isEligible` after the entry fetch); a word without a usable sentence is dropped there and the next reserve
  companion, as unsuitable, takes its place. Fix: the server tells the client, per entry, which of these kinds it can
  make (a new route over the same rules the cards use), the client keeps that as a per-session **eligibility index**
  and planning never plans a companion the index rules out. The modal's "This session", the home widget's counts and
  the session counter are then one plan.
- **#289.** The modal (and Advanced) offer a card type only when the selection has at least one card of it to study
  now (due or new, the Study all plan, companions counted only where the word qualifies). A hidden type keeps its
  stored choice; one line under the chips says which types are hidden and why.

## Rulings

- Ruling: the server decides every companion kind (`sentence`, `writing`, `tone`, `reverse`, `cloze`) — they need
  entry data only the server has for every card at once: the sentences the user may see, the segmenter, readings after
  the user's patch, senses, and which characters the *installed* strokes packs cover (the bundled hanzi-writer index
  the level planner uses lacks Japanese forms such as 読, so it would have hidden writing for many Japanese words) —
  cost: none known; the card's own snapshot check (a Han character) stays on the client.
- Ruling: route `POST /api/study/eligibility {"ids": [1..500]}` → `{"entries": {"<id>": ["sentence", …]}}`, every
  asked id answered (an unknown entry `[]`), kinds in kind order; `accUser`, `noTok` (no token use case), no
  service-worker caching (offline sessions plan no companions at all) — a POST because 500 ids do not fit a URL —
  cost: none known.
- Ruling: the rule (`cards/eligibility.json`) is the show-time rule moved to planning: sentence = a sentence with
  non-blank text; writing = a Han character with stroke data, not a character entry without glosses; cloze = one of the first 8 non-blank sentences has a blank (`cloze.json`, the server's
  `ContainsWord` over its own segmenter); tone = a tonal language and a clean toned pinyin reading; reverse = a word
  entry with a gloss. The user's own sentences and overlay readings count; another user's never — cost: a client that
  shows a card snapshot in kana (starter kana rows) may still find a cloze blank-less at show time; the show-time
  check stays and drops it (below).
- Ruling: Japanese cloze and inflected forms: the server segments with the dictionary segmenter and its deinflection
  (lemma rules, lemma packs), the same `/api/segment` the card uses, so 食べた in a sentence counts for 食べる and the
  card blanks 食べた (the cloze contract already blanks the surface); tested in Go. A language the server cannot
  segment gets no cloze (the card could not segment it either) — cost: none.
- Ruling: the index is per session (cleared on sign-out), entries are re-asked after 10 minutes, and adding or keeping
  a sentence forgets that entry; unknown entries (not asked yet, or the request failed) are planned as before and
  checked when shown — honest counts need the answer, and a failed request must not silently remove card types; the
  modal, Advanced, the widget and the session wait for the index before counting (the modal shows its loading line)
  — cost: a failed index request brings back the old over-count for that session; a reload asks again.
- Ruling: `ineligible.ts` (the per-tab sessionStorage memory) is replaced by the index: a show-time drop that
  `rememberDrop` calls final removes the kind from the entry's index row, so the rest of the session (and the modal)
  agrees — one source instead of two — cost: the memory no longer survives a reload of the tab; the server answer
  makes it unnecessary.
- Ruling: a show-time drop (a race: a pack removed after planning) still frees the slot for the next reserve item
  (`dropItem`), and the reserve is now only eligible items, so the counter never drops by more than the cards removed.
- Ruling: the home widget's "new left today" counts the companions the session would plan, admitted by the daily
  limits like real new cards (companions share the new allowance) — before it counted real cards only, so it said
  "0 new" while the modal said 20 — cost: one index request on the home page per session.
- Ruling: a type is *available* when the Study all plan of the selection (no session cap, no daily limit, burying and
  vacation applied, companions only where the index allows) holds at least one item of it; each opt-in kind is
  planned in its own pass (a word with a queued card gets no opt-in companion, and at most one opt-in per word, so
  next to Vocab they would look empty); in the modal an opt-in chip also still needs a selected deck that switches it
  on — "due or new" from the issue; Study all, not Start, because a type whose new cards wait only on today's limit
  still has cards — cost: up to three extra plan passes when the modal or Advanced renders.
- Ruling: "This session" is now the length of the queue Start plans with the saved limits (one more plan pass), not
  `min(due, reviewLimit) + min(new, newLimit)` of the uncapped plan — that estimate (study-modal plan, Ruling 2) missed
  the opt-in companion of a word whose due card the review cap leaves out; the counts match the queue exactly (tested
  over a grid of limits) — cost: one plan pass.
- Ruling: when the selected types have nothing but another type has, the today line says "Nothing is left to study
  with the chosen card types. Choose another one." (new string) instead of "nothing is due" — cost: one string.
- Ruling: Advanced hides the non-opt-in types the same way; its Reverse and Cloze switches write every deck's
  settings, so they show when the kind would have cards if switched on (the pass enables it for the selected decks)
  — deck settings stay the way to prepare a deck with no cards yet (the issue) — cost: a kind that would have no card
  even switched on cannot be switched on for all decks from Advanced; the per-deck switches still can.
- Ruling: hidden types are named in one muted line under the chips, grouped by reason: no example sentences (Word
  Salad, Cloze: no word in the selection has one), no characters to write, no clean pinyin, or nothing to study now;
  for an administrator the sentence reason adds the `qinqin seed` hint — the issue's "says why" without a line per type
  — cost: four short strings.
- Ruling: "at least one chip stays selected" counts the visible chips; a hidden type's stored choice is kept and
  comes back with its cards; when no selected type is visible the today line asks to choose one and Start is off.
- Ruling: no new `ineligible`-style storage, no localStorage copy of the index — a reload asks the server again
  (≤ one request per 500 cards) — cost: a cold modal waits for that request.
