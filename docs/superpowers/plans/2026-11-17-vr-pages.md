## The per-page checklist (binding for every page below)

Each page task proves these with tests (source checks through the style walk and per-page dom tests):

1. **Base components** — buttons are `Button` / `IconButton`, text inputs `Field`, choices `Select`, tabs `Tabs`,
   dialogs `Dialog`, groups `Section` (titled, unboxed), menus `Menu`, chips `Chip`, numbers `Stat`; the one box
   is `Panel` with a stated reason. Raw `<button>`, `<input>` (text-like types) and `<select>` in a page file
   are findings of the `control` rule (checkbox, radio, file, range, colour and the OTP digits are allowed;
   anything else needs an allowlist entry with a reason).
2. **Hairlines** — separators and outlines are 1px `--hair` (or `--line` for a control's underline); no border
   wider than 1px except the 2px accent underline of a selected tab / focused field and the focus ring; no
   shadow except `--shadow-float` on floating layers; no filled boxes around groups.
3. **One primary action per view** — at most one `Button variant="primary"` (or the rare `filled`) visible at a
   time; secondary actions hairline-outlined, tertiary plain text; destructive actions `tone="danger"`
   secondary, never primary. A view = what is on screen in one state (a sign-in step, a settings tab, an open
   dialog counts as its own view).
4. **Underline fields** — every text field, search and select is an underline (`Field`, `Select`); labels above
   in the label style; hint and error linked.
5. **Sentence-case labels** — every visible label, heading, button and tab text is sentence case ("Add deck",
   not "Add Deck"; no `text-transform: uppercase`, no all-caps strings); proper names keep their capitals
   (allowlist: product, palette, dictionary, scheme and language names, HSK, JLPT, FSRS, AI, API, TOTP, SMTP, …).
6. **Type ≤ 600** — no `font-weight` above 600 (`bold`, 650, 700, 800, `bolder` are findings); `b` / `strong`
   are 600 through `app.css`; headings 600; big numbers 400–500.

Plus, on every page: tokens only (the existing lints), every string through the catalogue, the page's `h1` kept,
keyboard order and focus unchanged, live regions unchanged, forced colours readable, no horizontal page scroll
at 360px (wide tables scroll inside their own wrapper, as today).

**Layout rule:** "no new layouts are invented without showing the owner". A restyle may change *how* a region
looks (boxes → space and hairlines, controls → base components, spacing → tokens) and may stack columns on a
phone where the page already wraps. It may **not** move regions, merge or split pages, change the tab or section
structure, reorder a form, or add a region. Anything that would is written as `Ruling: <kept as is> — <the
layout question> — <cost>` and as an **Owner check** line; it is not built in this item.

## Architecture

- **Page manifest** `apps/web/src/lib/ui/lint/pages.ts` (new): `PAGES: {route, files: string[], owner: '#99' |
  … | '#106', views: string[]}[]` — the table above. `pages.test.ts` walks `src/routes` for `+page.svelte` /
  `+page.ts` and asserts the set of routes equals the manifest's; every listed file exists.
- **Style walk** (PART B's `lib/ui/lint/colourWalk.test.ts`, renamed or extended — keep one walker): new rules
  in `lib/ui/lint/restyle.ts` with unit cases in `restyle.test.ts`:
  `weight` (font-weight > 600 or `bold`/`bolder`), `caps` (`text-transform: uppercase|capitalize`,
  `font-variant: small-caps`), `border` (a `border*` width above 1px outside `:focus-visible` / `[aria-selected]`
  / `[aria-current]` / `.selected` rules; `outline` is not a border), `shadow` (a `box-shadow` that is not
  `var(--shadow-float)`, `none`, or an `inset 0 0 0 1px` / `inset 0 -1px 0` hairline), `control` (raw
  `<button`, `<select`, `<input` of a text-like type in a file the page manifest names; `lib/ui/**` exempt).
  Ratchet: `pending.json` gains the five lists from the current findings (`UPDATE_STYLE_PENDING=1`), each page
  task removes its files, the final task asserts every list is empty for the pages' files; `allowlist.json`
  entries need a reason.
- **Sentence case** `apps/web/src/lib/i18n/sentenceCase.test.ts` (new) with `sentenceCase.ts`: every catalogue
  value whose key matches a label-ish namespace (`*.title`, `*.label`, `*.action.*`, `*.tabs.*`, `*.heading`,
  button and column keys — the list lives in the test and is reviewed) is sentence case: no word after the first
  starts with a capital unless it is in `sentenceCaseNames.json` (proper names) or follows a colon, a full stop or
  an arrow ("Settings → Features"), and no value is all caps. Ratchet list `sentenceCasePending.json` like the
  style walk; fixes change **values only**, never keys; translator notes unchanged unless the meaning changes.
- **Primary-action helper** `apps/web/src/lib/ui/testing/primary.ts` (new): `primaryActions(root)` returns the
  visible elements rendered by `Button` with `variant` `primary` or `filled`; every page dom test asserts
  `toHaveLength(1)` (or 0 where a view has no action) per view.
- **Global element styles** in `apps/web/src/app.css` (one block, tokens only): `b, strong { font-weight:
  var(--weight-strong) }`; `input[type=checkbox], input[type=radio], input[type=range], progress { accent-color:
  var(--accent) }`; `fieldset` without border and padding, `legend` in the label style; `.ui-table` (opt-in
  class: hairline row separators, `th` in the label style — sentence case, `--readable-muted`, weight 500 —
  numeric columns `tabular-nums`, no zebra, no outer border).
- No new route, no Go change, no new dependency.

  B; P12–P14 only check).

  focusable with a name when it scrolls (as today on Sources).
- Checkboxes and radios keep native semantics and visible labels; a coloured state always has text.
- Forced colours: underlines, hairlines and the selected tab use system colours (the base components do this);
  page-level `@media (forced-colors: active)` blocks that exist today are kept.
