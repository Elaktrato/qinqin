# Plan — browser end-to-end tests with Playwright, run in CI (#157)

Part of #190, phase 1. Branch `feature/157-e2e` from `develop` at a609a10f, worktree `.claude/worktrees/157-e2e`.
The owner authorised browser automation for this suite (the pre-installed Playwright locally; CI installs its own
Chromium). The suite is the test: each flow is shown failing against a deliberately broken build. One commit per
task.

## Scope (owner, 2026-11-23)

The five required flows are the safety net for the phase 2 and 3 refactors and must stay green through them:

1. Signing in.
2. A study session: going back a card and changing the grade (#131, Back and Z); card types interleaved in one
   session (#132).
3. A reader lookup: open a Japanese text, point at a word, the popup shows the dictionary entry.
4. An offline study session that syncs exactly once when back online (service worker and pages cached first;
   Playwright's offline mode; the server receives each review once, no duplicates after a reload).
5. The phone bottom bar (#188) at 360 px, and Settings → Layout → Side menu switching back to the side menu.

The issue lists more flows; each one is added only if cheap and stable (Ruling below).

## Design

- **Where:** `apps/web/e2e/` — `playwright.config.ts`, `support/` (build, server, API, fixtures, epub, study
  data), `fixtures/packs/` (two tiny dictionary packs), `tests/*.spec.ts`. Run with `npm run e2e` in `apps/web`.
- **What runs:** the real binary with the built SPA embedded. The global setup copies `server/` to a scratch
  directory, puts `apps/web/build` (built when missing) into `internal/webdist/dist` and runs `go build`, as
  `scripts/smoke-embed.sh` does; the worktree is not touched. `QINQIN_E2E_BINARY` skips the build (a mutation
  build, a prebuilt binary). Then `qinqin seed` imports the fixture packs into a template data directory and
  `qinqin adduser --admin` adds the admin: well under a second.
- **Per worker:** a copy of the template data directory, a free loopback port, `QINQIN_AUTO_SEED=0`, an empty
  `QINQIN_PACKS` root, no `QINQIN_SECRET` (no AI, no stored mail), no SMTP. The server log goes to the test
  output folder.
- **Per test:** a fresh learner (registered with the admin's token, signed in through the API) and a browser
  context holding that learner's token in `localStorage` (`qinqin.token`); the sign-in and register tests start
  signed out. Study data is pushed through `POST /api/sync/push` in the contract shapes; a book is a minimal
  epub built in memory and uploaded through `POST /api/library/upload`.
- **Assertions** use role and text locators and the API (from Node, unaffected by the browser's offline mode);
  no app storage keys except the session token the fixture plants. No sleeps: every wait is a web-first assertion or
  an `expect.poll` on a condition.

## Rulings

- Ruling: the suite lives in `apps/web/e2e/`, outside `src/` — it tests the web app through the browser, uses
  the web package's dependencies and build, and `src/lib` folder rules (record 0004, #195) do not reach it; vitest
  only collects `src/**` — cost if wrong: a `git mv` to a root `e2e/` with its own `package.json`.
- Ruling: `@playwright/test` is pinned to the exact version of the pre-installed Playwright (1.63.0) — that
  version's Chromium build is the one installed here, so no `executablePath` is needed locally; CI installs the
  matching browser with `npx playwright install --with-deps chromium`; a bump is a deliberate change. A different
  local browser is set with `QINQIN_E2E_CHROMIUM` — cost if wrong: one version bump.
- Ruling: no server clock hook. Scheduling, the study day and due cards are computed in the browser; the fixture
  writes study data relative to the real current time (an earlier review "3 days ago", graded Easy, so it is
  neither due nor burying today), the browser runs in `UTC`, and nothing asserts a date. Playwright's
  `page.clock` is not used: it would also freeze the service worker's and the app's timers — cost if wrong: a
  test that needs a fixed day adds `page.clock.setSystemTime` (timers keep running) or a server hook then.
- Ruling: the session's shuffle is made deterministic by seeding `Math.random` in the page (`seedRandom`); the
  mix (#132) seeds from it at Start. Event ids use `crypto.getRandomValues` and stay unique — cost if wrong:
  a change of the mixing algorithm can make the seeded order differ; the test then names the new order and the
  seed or the expected first types are adjusted.
- Ruling: every test gets its own user; tests never share study data, so they run in any order and in
  parallel (two workers) — cost if wrong: none found; a registration costs a few milliseconds.
- Ruling: the fixture signs learners in through the API with an `X-Forwarded-For` address of their own (the
  server trusts loopback, `QINQIN_TRUSTED_PROXIES=127.0.0.1`), so the per-address sign-in limit (burst 10, one
  per 6 s) never trips as the suite grows; the browser sign-in test uses the real address — cost if wrong: none.
- Ruling: after a push the fixture waits until a pull round ships the pushed cards. A round ships rows stamped
  before its `until` (whole seconds), so rows written in the second the page loads arrive only with the next
  round, and the study page does not re-read after the first round — cost if wrong: none; it is a condition
  wait, not a sleep. (A real device writing in that same second shows the card on the next visit.)
- Ruling: retries 0. A flaky test is fixed or quarantined with `test.fixme` and an issue, never retried —
  the issue's own constraint — cost if wrong: a red gate on a flake, which is the signal wanted.
- Ruling: **release-blocking vs nightly** — the whole suite is the gate: it runs on every push to `develop` and
  `main` and on every pull request, and a red e2e job blocks a merge like the unit tests. It takes about 15 s
  locally (2 workers) and a few minutes in CI (browser install, binary build). A nightly run is not needed
  while the suite stays this small; split smoke/full when it passes about 5 minutes of test time — cost if
  wrong: slower pull requests, then split.
- Ruling: **browsers** — Chromium only, gate and everything else. No Firefox/WebKit nightly now: the app's
  risky paths (service worker, offline, IndexedDB, Cache Storage) are where engines differ, but a nightly that
  nobody watches rots, and WebKit on Linux is not Safari on iOS, the browser that matters. Revisit with the
  Android work, or when a Firefox/Safari bug report arrives — cost if wrong: an engine-specific bug found by a
  user instead of the suite.
- Ruling: **visual snapshots** — none. Functional assertions only: pixel snapshots break on font and
  rendering changes across runners and would block the visual work; the component gallery (#98) covers looks —
  cost if wrong: a pure layout regression (an overlap) is not caught; the bottom bar test checks its position.
- Ruling: **axe accessibility checks** — not now. The tests use role and name locators throughout (a missing
  name or role fails them), which covers the landmarks and controls the flows touch; a full axe scan would
  report pre-existing issues across pages and needs its own triage issue — cost if wrong: contrast or ARIA
  issues off the tested paths stay unseen.
- Ruling: **artifacts** — traces, screenshots and videos are kept only on failure (`retain-on-failure`,
  `only-on-failure`), uploaded from CI with the HTML report and the server logs only when the job fails, kept
  7 days — cost if wrong: a failure older than a week cannot be inspected; re-run the job.
- Ruling: the conventions live in a new record 0007 plus one line in record 0005 pointing to it — e2e has
  its own decisions, enforcement and open questions, more than a line holds; 0005 stays the entry point for
  test conventions — cost if wrong: merge the two records later.
- Ruling: the #197 wall-clock guard (`lib/testing/noWallClock`) scans `*.test.*` files only, so it does not
  read the e2e specs (`*.spec.ts`); that is right and is left so. A browser test has timeouts as hang
  backstops, and the suite's own guard (`tests/conventions.spec.ts`) forbids fixed sleeps instead — cost if
  wrong: none.
- Ruling: the extra flows from the issue — done: search + add to study, workspace switch, registration (open
  mode). Not done: admin users, backup download, journal entry (they need more fixture or admin re-auth flows
  and are covered by unit/DOM tests), the update bar (needs two builds with different ids served in one run),
  grammar lessons (no grammar pack in the fixture). Each is a candidate for a later, separate test.

### Fix wave (independent review)

Each strengthened assertion was run against the reviewer's surviving mutation, rebuilt in a scratch copy of
`apps/web` and run through `QINQIN_E2E_BINARY`; "old" is the suite before the group, "new" after.

- **Study (must-fix 1, should 6).** The test reads each card from what the learner sees (the heading's
  accessible name parsed with a regex, and the prompt: the word of a Recognise card, the meaning of a Recall
  card). After Z and after Back it asserts that the graded card's word is on the face again and the current
  card's is not; after the regrade, that the current card is the next one, unanswered. The Z-in-the-answer-field
  check runs at the first Recall card wherever it lands; the seed only keeps runs repeatable, and the
  replaced reviews are checked to be those of cards 1 and 3. mB (`shownCard = $derived(resolved)`): old passed,
  new fails ("Expected substring: 学校", the face showed the current card).
- **Phone navigation (must-fix 2, should 7).** The bar's bottom edge must be within a pixel of the screen's
  bottom (and the bar in the viewport) on Home, mid-way down and at the end of the long Settings → Layout page,
  and after switching back; a second item (Decks) is clicked and checked too. The "choice belongs to the
  account" check no longer reads the `nav-layout` plugin row (#199 removes that route): a fresh browser
  context with only the session token opens in side-menu mode. mC2 (`position: static`): old passed, new
  fails ("toBeInViewport … ratio 0"). mC (`inset-block-end: -200px`): old failed only by the 60 s click
  timeout, new fails at the same assertion in about 11 s.
- **No network (should 9), token key (nit 13).** The `context` fixture routes every http(s) request to a host
  other than the loopback server to an abort and fails the test on teardown when there was one; shown with a
  throw-away spec fetching `https://example.com/x` ("requests to hosts other than the local server"). The
  suite passes with the guard on, the service worker and offline mode included. The token key stays in one
  helper (`signedInState`) with a comment naming `TOKEN_KEY` in `apps/web/src/lib/api/client.ts`: that module
  imports the app's offline state and cannot be loaded by Playwright on its own.
- **Reader (nit 12).** The fixture gains 学 (a character) and 学生; the book a paragraph with 学生. The test
  asserts the ranking (学校 before 学 when pointing at 学 of 学校), then points at 学 of 学生 after 学校 was
  looked up and expects 学生's entry (がくせい, student, then 学) and no "school". mD (the lookup cache keyed on
  the window's first character): old passed, new fails ("Expected substring: がくせい").
- **Offline (should 3, 4, 5).** The four cards get four different grades (Again, Hard, Good, Easy; the Again
  card's practice re-show is not recorded); each server review must carry its card's grade, and its `ts` must
  lie between the session start and the second of the last grade. The test waits (a poll on the clock, not a
  sleep) until the clock is past that second before going online, so a review stamped at sending time is told
  apart from one stamped at grading time. The outbox key is gone from the test: offline it reads the "N reviews
  are saved on this device" line, online "All reviews sent." and the server's count. After the reload the test
  waits until the Study page has read the history back from the server (0 new left) and no saved-reviews line
  shows, then compares the server's review ids. mE (the flush rewrites `ts` to the flush time and the grade to
  3): old passed, new fails (私: grade 1 expected). The `ts` half alone (mEts): new fails ("graded at …:21Z,
  expected <= …:20Z"); a first version comparing with the moment before going online passed mEts (same second
  after truncation) and was tightened.
- **App bug (a) (own commit).** `prepareOffline` now plans the kinds a session started now would study:
  the tab's own setup, else the kinds last started in the workspace, else vocab, plus each opt-in kind a deck
  in scope switches on and the learner has not unchecked — `effectiveKinds` in
  `apps/web/src/lib/study/cardTypesMemory.ts`, the rule the home widget and the deck start already use and the
  Study page builds from the same parts (`enabledKinds`, `defaultExtraTypes`); the runtime passes the tab setup,
  the remembered kinds and the choices. Test first: the new `prepareOffline` unit case (a learned word's new
  reverse card, General switching reverse on, no tab setup) failed ("expected … to include
  '/api/entries/9'"), then passed; it also checks an unchecked reverse is not prepared. The new e2e case (私 new,
  水 learned with a new reverse card, the Study page never opened online) failed against the old build at
  "Offline: ready - 2 cards saved" (1 was saved), and passes with the fix: both cards load offline and both
  reviews reach the server. Ruling: the shared helper is the existing `effectiveKinds` rather than a new one;
  the Study page keeps its own composition because it also shows each checkbox — cost if wrong: a later change
  to the rule must touch both, which the widget and deck start already share.
