# Contracts

Rules every qinqin client (Go server, web, future Android/Kotlin) must implement identically. Each rule
has a folder with a README (the rule) and JSON fixtures that all implementations run.

Fixture format: `{"version": 1, "rule": "<name>", "cases": [ ... ]}`. Go tests read the files with
`os.ReadFile` (relative to the test's package), web tests import the JSON directly
(`resolveJsonModule`). A fixture is only changed after re-deriving the value from its source of truth;
never to match an implementation. Add one row per area; a Go or web test must decode each fixture.

| Folder | Rule |
| --- | --- |
| [`study-day/`](study-day/README.md) | The learner's day: per-user zone history, `dayOf`, `dayStart`, `GET/PUT /api/me/time-zone`. Fixtures: `day-of.json`, `day-of-transitions.json`, `day-start.json`, `activity-days.json`, `time-zone-api.json` (Go: `studyday`, `stats`, `api`; web: `lib/time/studyDay.test.ts`) |
| [`levels/`](levels/README.md) | Level sessions of character schemes: unit/kind rules, writing unlock by learner day, ordering, virtual and created card ids. Fixtures: `character-level-queue.json`, `level-card-ids.json` (web: `lib/study/levelQueue.test.ts`, `cardFlow.test.ts`) |
| [`auth/`](auth/README.md) | Sign-in throttling (order of checks, status codes, `Retry-After`, JSON error bodies of login and register: `auth/throttling.md`, `auth/throttle-responses.json`) and sessions (token handling, 401 vs 403, restrictions, login statuses, device names, the one error-code catalogue: `auth/README.md`, `auth/errors.json`, `auth/login-responses.json`, `auth/me.json`, `auth/sessions.json`, and the registration and administration files `auth/options.json`, `auth/invites.json`, `auth/admin-users.json`, `auth/reset.json`; Go: `api/contract_auth_test.go`, `api/contract_accounts_test.go`) |
| [`cards/`](cards/README.md) | Reverse and cloze cards: card ids and `cardKey`s, sibling burying until the learner's next day, cloze sentence/blank choice. Fixtures: `card-ids.json`, `burying.json`, `cloze.json` (web: `lib/study/cardIds.contract.test.ts`, `siblings.test.ts`, `cloze.test.ts`) |
| [`decks/`](decks/README.md) | Flashcards decks view: deck and overall numbers (studied, mastered, due, 30-day reviews, retention), deterministic ids of copied system decks, the idempotent add-to-deck plan, `POST /api/entries/bases`. Fixtures: `deck-stats.json`, `system-deck-ids.json`, `add-to-deck.json` (web: `lib/plugins/flashcards/decks/*.test.ts`) |
| [`backup/`](backup/README.md) | Personal backup archive (zip of JSON, format v1): entry names, row shapes, caps, version rule, remapping of entry/card/workspace/book ids on restore, what is never included. Fixtures: `sample-v1/` (unpacked archive), `remap.json`, `reject.json`; error codes in `auth/errors.json` (Go: `backup/*_test.go`, `api/contract_backup_test.go`) |
| [`reader/`](reader/README.md) | Reader display: the per-workspace `reader` settings object and its parse rules, furigana alignment, the smart reading rule (known = vocab `cardScore` at or above the threshold, book ruby), `POST /api/segment` `readings`. Fixtures: `display-settings.json`, `furigana-align.json`, `smart-readings.json` (web: `lib/plugins/reader/displaySettings.test.ts`, `furigana.test.ts`, `smartReadings.test.ts`) |
| [`scheduler/`](scheduler/README.md) | Vacation mode and daily limits: `vacation:*` rows to runs and edit plans, the study clock `v`/`inverse` (whole-day shifts), replay and optimizer steps on it (generated from plain ts-fsrs by `scripts/contracts/gen-scheduler-fixtures.mjs`), the due rule, streaks, `limits:*` rows and the daily admission. Fixtures: `vacation-days.json`, `study-clock.json`, `vacation-schedule.json`, `optimizer-steps.json`, `due-today.json`, `streak.json`, `limits-rows.json`, `daily-limits.json` (web: `lib/study/{vacation,studyClock,scheduler,studyContext,limits}.test.ts`, `fsrs/dataset.test.ts`, `exp.test.ts`) |
| [`pwa/`](pwa/README.md) | Installable web app: which API reads a service worker may keep offline (allowlist), the per-credential cache partition rule, the per-user review outbox v2 (adoption, per-user flush, 30-day expiry) and the unchanged review event with idempotent ULIDs. Fixture: `outbox-v2.json`; the route table `apps/web/src/lib/pwa/sw/routes.fixture.json` (Go: `api/routes_fixture_test.go`; web: `lib/study/outbox.test.ts`, `lib/pwa/sw/classify.test.ts`) |
