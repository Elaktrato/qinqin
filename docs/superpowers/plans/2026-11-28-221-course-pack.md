## What

- **A `course` pack type** (record 0008: migration, type package `server/internal/courses`, one row in each half of the
  pack-type table, contract row, web type and label). Format `course-json`: one `course.json` holding only the
  project's own content (CC BY 4.0): sections with a target level, units with stable ids, title, topic ids, grammar
  points, hanzi/kanji, a reading text and an optional focus, and the checkpoint rules. **No level-list words.**
- **Fixture courses** `plugins/samples/zh-course-mini` and `ja-course-mini` (tests only; the real skeletons are #223).
- **The fill rule** (`courses.Fill`, pure): installed level pack (or the frequency estimate), topic labels and
  frequency ranks → each unit's words and lessons, the unplaced words. The server gathers the inputs from the
  installed packs (`courses.Gather`), fills and caches the result per course and per input fingerprint.
- **Routes** `GET /api/courses` (installed courses) and `GET /api/courses/{id}` (the filled course, ETag).
- **Progress events** `course` in the event log (`{kind, …}`: lesson started/finished, unit test, section exam,
  placement) and **the derivation** events → path state, in Go (`courses.Derive`) and TS
  (`apps/web/src/lib/studycore/courseProgress.ts`), agreeing on the same fixtures.
- **Contracts** `docs/contracts/courses/`: `pack.json` (the pack format), `fill.json` (fill rule), `derive.json`
  (derivation), `changes.json` (content changes); ContractVersion 23.
- **Backups/deletes:** course progress lives in the event log, so backup format 2 and the workspace/account deletes
  already cover it; a round-trip test pins it. `course_packs` is a server table (packs), not a workspace table.
- **Docs:** wiki `Courses-data-model.md`, `Data-pack-format.md`, record 0008 "Touched by", events README, CHANGELOG,
  NEXT.md.

## Rulings

Format: `Ruling: <what> — <why> — <cost if wrong>`.

### Pack format

1. Ruling: **one data file `course.json`, format `course-json`, stored raw in the registry row** (`course_packs.course_json`
   with a `content_hash`, like `lemma_rule_packs`) — a course is tens of units and a few hundred KB at most; no data
   tables to diff, a re-import of the same bytes writes nothing — a course grown past a few MB would want rows (#223
   sees the real size; cap 2 MiB).
2. Ruling: **no data package** (the type's `Package` is empty, like `images`); clients read the filled course from
   `GET /api/courses/{id}` and #222 keeps a copy for offline use — the filled result depends on the server's installed
   level packs, which a static package cannot carry, and the HSK words must not travel inside a course package —
   #222 must cache the route's answer (by its ETag) for offline lessons.
3. Ruling: **several live courses per language are allowed**; courses are addressed by pack id — nothing in the
   design limits a language to one course, and a second course (a business-Chinese course) is plausible — #222/#225
   must pick one per workspace (the first by pack id when the learner has not chosen).
4. Ruling: **titles are `{en: …}` maps** (`en` required, other interface languages optional) — interface languages
   (#144, #145, #297) come later in this milestone and the format needs no change for them — a slightly heavier file.
5. Ruling: **a section's `level` is the 1-based position of a level in the course's level scheme**, not a level name;
   `null` for a start section (sounds, script, Starter's base set) that gets no words — positions work for the
   frequency fallback too, where no names exist — a scheme that reorders its levels moves the course's words.
6. Ruling: **the scheme and the fallback are named in the pack:** `levels: {scheme: "<levels pack id>", estimate:
   [maxRank per level]}`. With the scheme installed it is the source; else the first live frequency pack of the
   language (priority order) with the estimate's rank cut-offs; else no words (the source `none`) — the design asks
   for a frequency fallback but leaves the cut-offs open; the course author knows its target sizes — cut-offs set
   badly give lopsided sections, visible in the unplaced report and the counts.
7. Ruling: **a unit has `id` (`^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 64, unique in the course, never reused), `title`,
   `topics` (topic ids, #220), `grammar` (points `<packId>:<lessonId>`, #277), `characters` (each Han character at
   most once in the whole course), `text` (`{title, body, translation?}`), `focus` (`listening` | `speaking`,
   optional) and `test` (default true)** — what the issue lists, nothing more; `test: false` is for start units whose
   check is the script trainer — #223 may need more fields, a format change is cheap now (no compatibility).
8. Ruling: **checkpoint rules in the pack:** `checkpoints: {lesson: {questions}, unit: {questions, passPercent},
   section: {questions, passPercent}}`, the course defaults 80 % and 75 % (plan §4) and both must be 50–100 —
   #224 builds the tests; the pack carries the marks so a course can tune them — none.
9. Ruling: **the topic labels stay embedded in the server** (`internal/topics`), not in the course pack — the labels
   are CC BY-SA 4.0 (#220 ruling 18) and the course pack CC BY 4.0, and #220 built them as one shared file per
   language — the design's "the course pack holds … the topic labels" is not followed; moving them later is a
   format change only.
10. Ruling: **grammar points are not checked against the installed grammar packs at import**; the filled course marks
    each grammar lesson `available: false` when its lesson is not installed — packs install in any order, and a
    course must not fail because the grammar pack comes later — a typo in a point shows only as an unavailable
    lesson (the Go test of the fixture packs checks the bundled points once #223 ships them).

### Fill rule

11. Ruling: **the candidate words of a section are the words of its level** (scheme: the level's non-derived members;
    fallback: the frequency rows ranked into that level); words of levels without a section are out of scope and not
    reported — "keep each level's words in its section"; HSK 5–9 are beyond the course — none.
12. Ruling: **order = frequency rank** (first live frequency pack of the language; lower first), **then the level
    pack's order, then the key**; a word without a rank comes after ranked ones — "by frequency"; zh has no bundled
    frequency pack, so Chinese falls back to the level pack's order (alphabetical HSK) until one is installed — the
    Chinese order inside a unit is weak; #223 can add a zh frequency pack or order hints.
13. Ruling: **topics by entry key** (`topics.File.TopicsForKey`: every label row of the key, word row first, then
    senses) — the server holds entries, not the list's forms, and the key is what #220 labels by — a list form that
    resolves to another entry than the labelled one misses its label.
14. Ruling: **placement in two passes with per-unit quotas.** Quota: the section's candidates spread evenly over its
    units (`floor(N/k)`, the first `N mod k` units one more). Pass 1, in order: a word with topics goes to an allowed
    unit that shares its first matching topic and has room, the unit with the fewest words, ties the earlier. Pass 2,
    in order: every word left goes to the earliest allowed unit with room; with no room anywhere, to the allowed unit
    with the fewest words (ties earlier). All labels weigh the same (no `confidence` weighting) — topics first, then
    balance, then frequency, all deterministic; general words (`function`, `qualities`, … no unit has as a theme)
    spread over the section in frequency order, the common ones first (#220 ruling 2) — a unit with a popular theme
    holds no more than its quota of theme words.
15. Ruling: **hanzi/kanji first:** a word is allowed only in units at or after the last unit that introduces one of its
    characters (characters no unit introduces do not constrain); a unit's `script` lesson comes before its word
    lessons. A word whose character comes in a later section is **unplaced** (`reason: "character-later"`) — the
    section rule and the character rule cannot both hold; the report shows it to the author — such words are not in
    the course until #223 moves the character.
16. Ruling: **lessons of at most 7 words, as even as possible:** `m = ceil(n/7)` lessons, sizes differing by at most
    one, the larger first. 5–7 holds for every unit of 10 words or more and for 5–7; a unit of 1–4 has one short
    lesson, a unit of 8 or 9 two lessons of 4–5 — plan §4's 5–7 cannot hold for 8 and 9; a lesson never exceeds 7 —
    a few 4-word lessons.
17. Ruling: **lesson order inside a unit:** `script` (if the unit has characters), the word lessons `words-1…`, each
    grammar lesson after the word lesson `ceil(j·W/G)` (right after the script when the unit has no words),
    `practice` (if the unit has words), `reading` (if it has a text). The unit test is not a lesson (`test: true`) —
    grammar spread through the words rather than piled at the end; #222 hosts each kind — #222/#223 may reorder
    (a contract change).
18. Ruling: **lesson ids are derived within the unit:** `script`, `words-<n>`, `grammar-<lessonId>` (the grammar
    point's lesson part), `practice`, `reading`, and `catch-up-<n>` (derivation only) — design §7 — a word lesson's
    words can change with the packs; progress therefore records the words a lesson taught (ruling 21).
19. Ruling: **unplaced words are served in the route answer** (`unplaced`, with the reason) **and logged once per fill**
    — the design allows "an admin view or a log"; the list holds only level words, which the course page already
    shows to the same users — none.
20. Ruling: **the cache is in memory, per course id and input fingerprint** (course hash, scheme version, frequency
    pack hash, labels version, lexicon state); each request recomputes the fingerprint (a few small queries) and
    refills on a change — "cached per server" without a table; a restart refills on first use (well under a second
    for the real sizes, measured in Task 4) — none.

### Progress and derivation

21. Ruling: **one event type `course`, payload `{kind, course, …}`** with kinds `lesson-started {unit, lesson}`,
    `lesson-finished {unit, lesson, score, total, words}`, `unit-test {unit, score, total, passed, early}`,
    `section-exam {section, score, total, passed}`, `placement {section}`. A finished lesson carries the keys of the
    words it taught; a test carries `passed` as judged when it was taken and `early` (taken before the unit's lessons
    were done) — the derivation then never needs the course as it was at the time: content changes cannot rewrite
    history — a few hundred bytes per lesson event.
22. Ruling: **a unit is done when it is passed**: its own test passed (`test: true`), or all its lessons finished
    (`test: false`), or **skipped**: an early passed unit test skips every unit before it in the course, a passed
    section exam skips its section's units and every unit before, a placement into a section skips every unit of the
    sections before it — design §7 "passing it unlocks everything before it" — the unit test, not the last lesson,
    closes a unit, so a unit whose lessons are all done waits for its test.
23. Ruling: **words of skipped units are output as `known`** (never met, not already known): the client marks them known;
    **words of studied units** (passed by a non-early test or by finishing) that were never met nor known are the
    **catch-up lessons** of that unit (sized as ruling 16) — design §7; the client's known-word marks are the record
    that a skip already marked a word, so the derivation takes the known set as input — a word added later to a
    *skipped* unit is marked known too, not taught (judged right: the learner tested out of that unit).
24. Ruling: **position and unlocking:** the learner's position is the last done unit in path order; the current unit is
    the first not-done unit after it (the first unit when none is done); not-done units before the position are
    `unlocked` (units added before the learner's position, design §7); units after the current one are `locked`.
    Inside an open unit the current lesson is the first unfinished one; unfinished lessons before a finished one are
    `unlocked`; later ones `locked`; with every lesson finished the unit's `next` is its test — none.
25. Ruling: **a lesson never fails**: finishing it is enough; the score is kept for the summary — the design's lesson
    check is "short"; passing is what the unit test does — #224 may want a lesson retry, a client choice.
26. Ruling: **events of unknown courses, units, lessons or sections are ignored, except that their `words` still count
    as met** — a unit removed or renamed by an update keeps what the learner learnt — none.
27. Ruling: **no activity rule, EXP or milestone for `course` events here** — #225 owns milestones, home and goals; a
    lesson's cards and grammar runs already count through their own events — #225 adds them.

### Other

28. Ruling: **both routes are signed-in only (`accUser`), no personal-access token (`noTok`), no service-worker
    caching** — the filled course holds the HSK words, which are not public data; #222 caches the answer in the app —
    an extension or script cannot read the course (none planned).
29. Ruling: **the web derivation lives in `lib/studycore/courseProgress.ts`** (next to `grammarRuns.ts`), the decoder in
    `lib/api/courses.ts` — the progress is study-core data every feature may read; the course screens (#222) get
    their own feature folder — none.
30. Ruling: **migration 057** — next after 056 on the base; parallel builders may take it, the orchestrator renumbers.

## Later rulings (made while building)

31. Ruling: **a unit may name `scripts`** (writing-system ids of the scripts trainer, `hiragana` …); its `script`
    lesson then carries them — the start sections teach kana, which are not Han characters and so cannot be
    `characters` — #223/#222 decide what the trainer step shows.
32. Ruling: **a focus adds a lesson** (`listening` or `speaking`, after practice) — else a start unit with only a focus
    would have no lessons and be done at once — none.
33. Ruling: **lesson statuses are `done`, `next`, `unlocked`, `locked`** (`next` for the unit's next lesson, so it is
    not confused with the course's `current` unit) — none.
34. Ruling: **`met` is in the order first met, not sorted** — Go sorts strings by bytes and JavaScript by UTF-16 code
    units, which disagree for characters outside the BMP — none.
35. Ruling: **the event payload builder is one function `coursePayload(input)`** that writes the members in contract
    order, listed once in `events/payloads.json` (one builder per written type) — the five kinds share one type — none.
36. Ruling: **the cache checks a cheap fingerprint first** (lexicon version, frequency pack hash, scheme version,
    grammar packs, the course row) and gathers only on a change — measured: a cached answer took 0.4 s when every
    request gathered, 18 ms now; a fill of the 1,892 HSK 1–4 words 0.5 s — a write that changes none of those inputs
    (none known) would serve a stale fill until the next one.
