# #348 — reader: the Japanese segmenter reads whole sentences (2026-11-28)

Milestone v0.9.0. Branch `feature/v090-348-ja-segmenter` from `feature/v0.9.0` at `633844a9` (contract 33). Found by
the builder of #223 (course texts): the reader's greedy longest-match segmenter splits Japanese kana runs across word
boundaries (名前｜はア｜ン｜ナ, 妹｜がい｜ます, 仕事｜はち｜(ょっ)｜と, 花｜がき｜れい) and the first candidate of a lone
particle can be a noun read by its kana (の → 野, で → 出), so particles show up as unreached, new words. This builder
does **not** hold the text-heavy slot: no written content, no teacher reviews; fixture sentences are short and
ordinary.

## Where segmentation lives

- **Server** `server/internal/segment` (`Segment`, greedy, plus the boundary rule of `docs/contracts/lemma/`) on top of
  `server/internal/lookup` (ranked results of every prefix and its deinflections, `lemma` rule table #165). Every
  client reads it: `POST /api/segment` (the reader, the course reading lesson, smart readings, word states,
  coverage), the eligibility and example-sentence services, the Tatoeba tool. `/api/segment/at` and `/api/lookup`
  are lookups at a cursor (longest match there), not segmentation: unchanged.
- **Web** segments nothing itself: `lib/api/segment.ts` calls the server; `features/courses/readingText.ts`,
  `features/reader/{wordRanges,coverage,smartReadings}.ts` read `entries[0]` of each match.
- **Contracts**: `lemma/README.md` ("Segmentation is greedy longest match", the boundary rule, `segment.json`);
  `reader/` (word states, coverage) reads matches. No shared segmentation-scoring contract existed.

## What

1. **Whole-sentence scoring for languages with segmentation rules** (Japanese): the segmenter looks up every position
   once (memoised), builds a lattice of edges (one per distinct matched surface at a position, head = its best ranked
   result) and picks the cheapest path by a backward dynamic programme; ties go to the longer edge at the earliest
   position, so where greedy was right the output is greedy's. Costs (contract `segment/ja.json`): every token 100;
   a weak kana-fit match (kana text read as a word usually written in kanji) +70; an all-kana match of an entry with
   priority 0 that is not a function word +30; a token starting between two kanji +100; an unmatched rune 250 (more
   than any token covering it); an exact reading match that differs from the reading as written and is one rune or
   mixes hiragana and katakana (はア for はあ, ナ for な) is no word. `splitWords` (今日は, 今晩は) are never one token.
   The boundary rule (`lemma/`) stays: when it would split the longest match at a position, that edge is dropped.
2. **Function words**: a small closed list of particles, the copula and auxiliaries (`segment/ja.json`
   `functionWords`), recognised when a token's lemma is in the list and one of its candidates has a function part of
   speech (`functionPos`: prt, cop, aux, aux-v, aux-adj). Such a token's head is that candidate (の the particle, not
   野), costs no penalty, and carries `function: true` in `/api/segment`. Clients: a function word is never new,
   learning or unreached — no reading or gloss in a reading lesson, no word-state line in the reader, not a coverage
   token.
3. **Chinese unchanged**: no `segment/zh.json`, so zh (and data-only languages) keep greedy, byte for byte. #349 can
   add `zh.json` with its own costs: the scoring is per language and parameterised.
4. **Contract 34** `docs/contracts/segment/`: README, `ja.json` (byte-identical to the embedded
   `server/internal/segment/rules/ja.json`), `cases.json` (a JMdict-shaped lexicon and texts with their tokens and
   function flags: the four issue cases plus verbs with inflections, い/な adjectives, kana-only words, katakana loans,
   numbers and counters), decoded by Go (`segment` contract test) and web (`readingText`, `wordRanges`, `coverage`
   tests). `lemma/README.md` and `reader/README.md` point at it. CHANGELOG, ContractVersion 34.
5. **Real data**: a `realdict` test on the shipped JMdict over ordinary sentences (the issue's four among them);
   a long-chapter timing (5,000 runes of Tatoeba sentences on the full JMdict plus the Jiten list), before and after,
   in the Execution record (env-gated test `TestBenchLongChapter`).

## Rulings

- Ruling: the lattice runs only for a language with a segmentation rules file (ja); zh and data-only languages keep
  greedy — the issue keeps Chinese unchanged and #349 is separate; a per-language file keeps the door open — cost if
  wrong: #349 adds `zh.json` and its fixtures, no engine change.
- Ruling: additive integer costs (token 100, weak +70, priority-0 kana +30, kanji split +100, unmatched rune 250),
  flat per token, not per rune — per-rune penalties made the DP split real kana words such as あめ into shorter good
  tokens; flat costs can only change greedy's choice where greedy's path covers the rest of the sentence worse. Tuned
  on 400 Tatoeba sentences against the full JMdict (Execution record) — cost if wrong: retune numbers in `ja.json`
  and the fixtures.
- Ruling: no discount for function words (they cost one token like any other) — a discount fixed は｜ついた but broke
  もの｜に into も｜のに (two cheap function words); without it such pairs tie and the longer edge wins — cost if
  wrong: はつ｜いた in あだ名はついた stays (greedy also got it wrong).
- Ruling: a token starting between two kanji costs +100 — without it an expression that starts inside a kanji word
  wins by being one token (仕｜事がある, 両｜手をあげろ); greedy never cut a kanji run it could match — cost if wrong:
  a correct cut inside a kanji run (あだ名｜付けられた) loses to a weak kana token (あだ｜名付けられた), seen once in 400
  sentences.
- Ruling: `splitWords` 今日は and 今晩は are never a token — JMdict's greeting 今日は (int, priority) beat 今日｜は in
  every 今日は… sentence of the course texts; the greeting is written こんにちは in learner texts — cost if wrong: the
  rare kanji-written greeting reads as 今日｜は (still both words looked up).
- Ruling: ties go to the longer edge at the earliest position (backward DP) — keeps greedy's output wherever scoring
  does not prefer another reading, so the existing `lemma/segment.json` cases hold unchanged — cost if wrong: none
  known; a tie rule change re-pins fixtures.
- Ruling: a reading match that differs from its reading as written is no word when it is one rune or mixes hiragana and
  katakana (はア → はあ, ナ → な, け → ケ); results, not edges, are dropped, so another result of the surface can stand —
  such a match crosses a script boundary or is a lone katakana letter of an unknown name; matches as written
  (サボる, メモする) and whole katakana words (ネコ → 猫) are unaffected — cost if wrong: a rare irregularly written
  word stays unmatched (still looked up on tap).
- Ruling: the boundary rule of `lemma/` stays as an edge filter on the longest match at a position — it encodes
  reviewed decisions (をして, であれ, に基づいて) that pure scoring would undo (an unprioritised expression is one cheap
  token) — cost if wrong: none; it only removes edges.
- Ruling: function words are a closed list in the contract **and** need a function part of speech on a candidate —
  the list alone would flag nouns that share a spelling, the part of speech alone would flag every JMdict conj/prt
  expression. し is left out (it is far more often する's stem: しなさい), as are ずつ, では, だろう and でしょう (no
  function part of speech in JMdict) — cost if wrong: extend the list.
- Ruling: one request-scoped memo of the store reads in `lookup` (`Cache`: entries by form and reading, frequencies,
  retired entries, dictionary names), used by every segmentation (zh too) — the lattice looks up every position and
  the same kana prefixes recur; results are identical by construction — cost if wrong: memory of one request's
  entries (bounded by the 5,000-rune cap).
- Ruling: a function word's head becomes its function candidate (の the particle, not 野) — the match's first entry
  decides word state, reading and the reached check; a particle read as a noun is the second half of the issue —
  cost if wrong: `entries` order differs from the lookup's ranking for these surfaces only; the popup still uses the
  lookup.
- Ruling: function words are not coverage tokens (like punctuation), rather than counted as known — they are grammar,
  not vocabulary; counting them known would raise every percentage and the read-next target with words nobody
  studies — cost if wrong: coverage numbers shift a few points; one branch in `coverage.ts`.
- Ruling: `function: true` is sent only when true (omitted otherwise), like `stem` — keeps the zh payload byte-identical
  — cost if wrong: none.
- Ruling: `/api/segment/at` stays the longest match at the cursor — it is a lookup at a pointer, the popup's rule
  (Yomitan-like), not a sentence reading — cost if wrong: a later issue can make it read the containing sentence.
