# #297 — choose the interface language per workspace (2026-11-27)

Milestone v0.9.0, phase 2. Branch `feature/v090-297-ui-language`. The issue has no owner comments; its body is the
spec. Today the interface language is one account setting (`me.interfaceLanguage`, #73), applied on the web before
mount from a localStorage mirror and followed after `me` with a guarded reload.

## What

- **A workspace-settings key `interfaceLanguage`:** absent (or `""`, or anything that is not a well-formed tag) = "use
  my account setting"; otherwise a language tag (`i18n/language-tags.json` syntax). Stored, synced and backed up with
  the other workspace settings; written by merge patch (`null` clears it). Contract 17.
- **Resolution (one rule, web and Go, fixture `settings/interface-language.json`):** the setting that applies is the
  workspace's when it has one, else the account's; then the existing negotiation (`i18n/negotiate.json`): that
  setting, else the browser's languages, against the catalogues that exist.
- **Web start and reload:** the mirror is kept per workspace (`qq.interfaceLanguage.workspace.<id>` holds the
  workspace's own setting; `qq.interfaceLanguage` keeps the account's resolved language). The root `load` picks the
  remembered workspace's mirror, else the account mirror, so a start (offline included) opens in the workspace's
  language. Once `me` and the workspace list are in, the root layout follows the current workspace: switching to a
  workspace with another language, or changing the setting, reloads once under the same guard as today (the next
  start must pick the language, its catalogue must differ, a sessionStorage marker bounds it to once per start).
- **Data-driven catalogue list:** `SUPPORTED_LANGUAGES` is derived from the files in `lib/i18n/messages/` (an
  `import.meta.glob`), so `de.json` and `ja.json` (#144, #145) become selectable in both settings by being added.
  The server's mail catalogue was already read from its directory.
- **Server text:** reminder mails follow the workspaces they are about (below); everything else (account mails, the
  unsubscribe page) keeps the account setting.
- **Settings UI:** Settings → Workspaces, for the current workspace, next to its study language: "Interface language"
  with "Use my account setting (English)" and one choice per catalogue. The account setting's hint says it is the
  default for workspaces that don't choose one.

## Rulings

- Ruling: the key is `interfaceLanguage` inside the workspace `settings` object, not a column or keyed row — every
  per-workspace preference lives there and it syncs, merges and backs up with no new code (#284 did the same) — cost:
  the server validates nothing on write; readers treat a malformed value as "use my account setting".
- Ruling: "use my account setting" is the key's absence; the UI clears it with `null` rather than storing `""` — one
  representation of the default, and a client that does not know the key behaves the same — cost: none (`""` still
  reads as the default).
- Ruling: the workspace setting stores a tag, not a resolved language: a workspace set to `de` before `de.json`
  exists resolves to English and becomes German when the catalogue lands — cost: the select only offers existing
  catalogues, so this happens only through another client or a restore.
- Ruling: "pages outside a workspace use the account setting" is read as **a page load without a workspace**: signed
  out (browser languages, as today: no account is known), an account with no workspace yet, and a restricted session
  that has no remembered workspace. The Account and Admin tabs of Settings live in the same page load as the
  workspace pages and keep the running language — the catalogue is chosen once per page load (spec #73 ruling: `t`
  is no store), so applying the account language there would reload the page on every tab switch — cost: someone with
  a German workspace sees Settings → Account in German; the account setting is described as the workspaces' default.
- Ruling: the per-workspace mirror holds the **workspace's own setting** (removed when it has none), the account
  mirror keeps the account's **resolved** language as before — a changed account setting then applies at once to
  every workspace that follows it, with no stale per-workspace copies — cost: none.
- Ruling: the reload after following is allowed only when the start it causes would pick that language
  (`startupLanguage` read back from storage for the workspace that is now selected), the catalogue differs from the
  running one, and no language reload happened at this start (the marker, as today); one follow runs when `me` and the
  workspace list are both in, and again whenever the current workspace, its setting or the account setting changes —
  generalising today's "the mirror reads back" check to two mirrors, so blocked storage or a mirror that would not be
  read can never reload in a loop — cost: when storage is blocked a workspace switch keeps the running language (as
  today for the account setting).
- Ruling: until the workspace list loads (offline start, a failing list) nothing is followed; the mirror's language
  stays — an offline start must not reload into the account language — cost: none.
- Ruling: the catalogue list is every `messages/<tag>.json` whose name is a well-formed language tag (`notes.json` is
  not), `en` first and the rest sorted — "no code change beyond registering them": adding the file is the
  registration — cost: a stray tag-named JSON file in that folder would be offered (the catalogue tests already check
  every catalogue file's keys).
- Ruling: a reminder mail counts every workspace with live facts in one mail, so it follows the workspaces it is about
  when they **agree**: each live workspace's applying setting (its own, else the account's); one value for all → that
  one; they differ, or none is live → the account setting — cost: a learner with a Japanese and an English workspace
  gets reminders in their account language.
- Ruling: there is no server-written weekly summary (the weekly summary is the web's Home widget and Stats, already in
  the running language); push and Android local reminder texts are written by the web app from the catalogue it runs
  (the current workspace's) — nothing more to change server-side — cost: a browser push planned in one workspace keeps
  that language until the app runs in another.
- Ruling: changing the account setting in Settings → Account still mirrors and reloads as today; when the current
  workspace has its own language the page comes back in it — cost: one reload with no visible change.
