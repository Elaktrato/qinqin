A run picks suites with `E2E_SUITES` (the workflow's matrix, or the `suites` input of a manual run). Every run does
the setup (server, seed, install, first-run screen, sign-in by token); suites after `shell` use their own learner
(B core and pages, C touch, D ime, P perf) so reviews and offline state never meet. The strokes pack the pads need is
generated by the driver (two characters, two straight strokes each; not stroke-order data, never committed).

## Rulings

- Ruling: the suites run as two matrix jobs (`core`, `extended`), not one long job — one emulator run of everything is
  ~25 min and one flaky step would hide the rest; two boots cost ~4 min extra but run in parallel. Cost if wrong: more
  runner minutes, and the build is done twice.
- Ruling: the nightly schedule runs both jobs; pull requests run both on the existing path filter (widened to the
  writing, flashcards and reader code) until the first stable runs say whether `extended` should leave PRs. Cost if wrong:
  a flaky `extended` blocks PRs, then it moves to nightly plus manual.
- Ruling: layout invariants fail the run (overflow, error, bar covering content, clipped header text, bar targets
  under 44 px); other small targets are only listed in the summary — many inline links are rightly small. Cost if
  wrong: a heuristic false positive costs one CI iteration.
- Ruling: the pads are driven with `adb shell input swipe` and `input motionevent` (a held multi-point path), not with
  DevTools touch events — only Android's own input path exercises the gesture recogniser and the system gesture zones.
  Cost if wrong: `motionevent` may be absent on an image; the vertical stroke then falls back to a swipe.
- Ruling: IME composition is simulated with `Input.imeSetComposition` / `Input.insertText` and a `keyCode 229` Enter
  through DevTools, not a real keyboard — the emulator has no Gboard dictionary and no handwriting; the manual
  checklist covers the real keyboards. Cost if wrong: a keyboard-specific event order goes unseen until a phone test.
- Ruling: performance numbers are a regression baseline on a software-rendered x86 emulator; they never gate a run.
  Cost if wrong: none for the build, a reader may mistake them for phone numbers (stated in the design doc and the JSON).
- Ruling: the emulator is allowed to lose the app (Google Play services restart): the driver waits for the services to
  settle first and retries idempotent steps after a relaunch (`resilient`). Cost if wrong: a step may run twice.

## IME audit (item 3a, Chinese/Japanese input)

Helper: `apps/web/src/lib/ui/ime.ts`. `isImeKey(e)` is true for `isComposing`, `keyCode === 229` (Gboard, Samsung, Safari) or a compositionstart..compositionend window plus 50 ms after the end (Safari fires compositionend before the confirming keydown). The same module cancels the default of an IME Enter in an `<input>` (safety net against implicit form submission on Android Chrome keyboards that send Enter with `isComposing` false).

## Review fixes (stage 2)

- Ruling: the IME guard no longer has a time window after compositionend; Safari's post-compositionend keydown is recognised by its keyCode 229, which `isImeKey` already checks — Gboard's genuine Enter after committing a Latin word has keyCode 13 and now acts (search, typing card; the implicit form submit is no longer cancelled) — if wrong, a browser that sends the post-compositionend Enter with keyCode 13 and isComposing false would act on it once (an extra search or check), found by the manual checklist.
- Ruling: the composition flag is reset on focusout, window blur, and lazily when the composing element is detached or no longer the active element — a detached input never sends compositionend and a stuck flag killed every Enter/Escape handler — if wrong, a composition that legitimately continues while focus is elsewhere would stop being guarded (not seen on any keyboard).
- Ruling: answer comparison keeps symbols (Unicode S: + $ = currency, maths) and the punctuation marks # % & @ at the edges, strips other punctuation and brackets, and falls back to the unstripped folded form when stripping would leave nothing — 'C++' is not 'C', '$5' is not '5', a symbol-only answer stays gradable — if wrong, a learner who types an edge symbol the dictionary form lacks (a trailing '~') is marked wrong; a visible miss, not a hidden accept.
- Ruling: the typing-card e2e step fails loudly when no typing field appears (no more ran:false pass). Cause found: opt-in chips such as Reverse start checked when the deck enables them, and the driver's click unchecked Reverse, so the session served Recognise. The driver now sets each chip to the wanted state — if wrong (the step still cannot run on CI), the suite fails visibly and the manual checklist item remains the fallback.
- Ruling: e2e sends Enter immediately after a commit (no sleep) in the search box and the typing card, covering the Gboard timing — if wrong, a slow emulator could mask the window, which weakens the check but never makes it red.
- Ruling (docs): the android-ime checklist claimed kana variants are folded; corrected: hiragana and katakana stay distinct (only half-width katakana folds, via NFKC).
