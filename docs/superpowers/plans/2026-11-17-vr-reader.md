> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (fresh implementer
> per task or per few tasks, independent review on the strongest model, one fix wave, whole-branch review).

**Goal:** the reader looks and works like design §9 "Reader": the text column gets the width (~40em, CJK at
~20px, line height ~2.2 for ruby); the side rail becomes a column of icons at the **right edge** (Contents,
Bookmarks, Highlights, Words, Display) opening a ~220px panel beside the text; word marks are new = thin accent
underline, learning = dotted `warn` underline, known = none, highlight = soft `warn` wash, selected word = accent
wash; the lookup popup appears **below the word** as a stack of entries (term, reading, level and frequency chips,
glosses, source, "Add to deck" / "I know this"). On the phone the rail moves into **one top-bar button** and the
lookup is a **bottom sheet** — the shared `Sheet` from `lib/ui` (#98), which the journal (#103) reuses for its
corrections. What the reader does (lookups, Shift+hover nesting, bookmarks, highlights, notes, words panel,
display settings, reading time, keys) does not change; the one data addition is the level of each lookup result.

## Architecture

- **Server (one data addition).** `server/internal/lookup` adds `Levels []Level{SchemeName, LevelName}` per result
  (one batched query over the result entry ids, like `frequencies`; the lowest level per scheme, the same rule as
  the entry page's badges in `internal/levels.ForEntry`). JSON `levels: [{scheme, level}]`, always an array.
  Web type `LookupResult.levels`. API docs regenerated.
- **Rail state.** `railState.ts`: `RailTab = 'contents' | 'bookmarks' | 'highlights' | 'words' | 'display'`
  (that order); `RailMode = 'column' | 'sheet'` (`'drawer'` goes); the stored state keeps parsing (an old
  `{open, tab}` stays valid; unknown tab → default).
- **Rail component.** `ReaderRail.svelte` is rebuilt: in `column` mode a 44px column of icon tabs at the right
  edge of the reader panel (`role="tablist"`, vertical, each tab an icon button with its name and a Tooltip
  placed `start`, roving tabindex, Arrow/Home/End as today via `tabKeyTarget`), the active tab marked by the accent
  icon and a short accent bar at the edge (§5 rail rule); the tab panel (`role="tabpanel"`, ~13.75rem / 220px) sits
  between the text and the icons with a `--hair` start line; activating the open tab collapses the panel (the
  column stays; the text never moves sideways). In `sheet` mode the rail renders nothing in the page; BookView puts
  one IconButton ("Contents, bookmarks, highlights, words and display", icon `contents`) into the frame's phone
  top bar, which opens the shared `Sheet` holding `lib/ui/Tabs` (icon + text tabs) and the same panel snippet.
- **Panels.** New `ContentsPanel.svelte` (chapter list with links, the current one `aria-current="page"`, prev /
  next as IconButtons). `DisplayPanel.svelte` becomes a rail panel (no disclosure of its own) and takes the script
  variant select that sat above the text. Bookmarks, Highlights, Words keep their components and tests; their
  headings and lists are restyled per §5 (unboxed, hairlines, `Section`-like small headings).
- **Text.** `BookView` / `ChapterText`: the reading column is `max-width: 40em` in the reader font at 1.25rem
  (20px), line height 2.2 (ruby needs it), centred in the space left of the panel; the book line above the text
  (title · author in CJK, the chapter title muted, a bookmark icon showing whether the paragraph in view is
  bookmarked); credits small and `--readable-muted` at the end; the chapter navigation becomes the Contents panel
  plus prev/next IconButtons at the end of the chapter.
- **Word marks** (global rules in `app.css`, shared with the Display legend and the Appearance preview): new =
  1.5px solid `--accent` underline, learning = 1.5px dotted `--warn` underline, no tint layer; known plain;
  highlights `--highlight-wash` (yellow) and the B2f mappings for the other colours; the looked-up word
  (`::highlight(reader-lookup)`) `--selected-wash`. Forced colours keep the `text-decoration` path (solid vs
  dotted, `CanvasText`), the looked-up word uses `Highlight`/`HighlightText`, user highlights `Mark`/`MarkText`.
- **Lookup popup.** `PopupFrameView.svelte` on tokens: `--panel` surface, 1px `--hair` outline, `--shadow-float`,
  `--radius-large`, width 18.75rem (300px), placed **below the word** by the existing `placePopup` (it flips above
  only when there is no room below — kept), close as an IconButton. `EntryCard.svelte`: term (1.5rem
  `--font-hanzi`), reading `--reading-accent` weight 500, `Chip`s for level(s), frequency and tags, numbered
  glosses with part-of-speech muted, the source line small muted, actions. `AddToStudyButtons.svelte`: a primary
  `Button` "Add to deck" (today's one-click add to General), a small IconButton (`expand-down`) "Choose a deck"
  that opens `lib/ui/Menu` with the decks (replacing its hand-made `role="menu"`), and a secondary "I know this"
  toggle (`aria-pressed`). Entries are separated by `--hair` lines (no boxes).
- **Phone lookup sheet.** New `LookupSheet.svelte`: below the phone breakpoint, `PopupStackView` renders the root
  frame's content inside `lib/ui/Sheet` (label = the looked-up text) instead of a floating popup; closing the sheet
  closes the lookup; nested Shift+hover frames do not exist without a mouse and keep the desktop popup path.
- **Fonts.** The reader stops going through `features/reader/fonts.ts` (its header says it stays "until the reader
  moves onto the shared module (#102)"): `READER_FONTS` / `ReaderFont` move into `displaySettings.ts`, the stack
  comes from `$lib/fonts/hanzi` directly, and `fonts.ts` is deleted.

## Global constraints

- **Tokens only** (the #98 lint is live): no literal colours, no `prefers-color-scheme`, no `Canvas`/`CanvasText`
  outside forced-colours blocks (the popup's `Canvas` background goes), secondary text `--readable-muted` (no
  `opacity` on text), separators `--hair` 1px, shadows only on floating layers (`--shadow-float`: popup, menu,
  sheet).
- **§5:** no boxes around the rail, panels or entries; one primary action per view (in the popup: "Add to deck");
  icon-only buttons have an accessible name and a tooltip (IconButton requires `label`); chips are `lib/ui/Chip`
  (no bordered pills); type tops out at 600.
- **Never colour alone:** word states keep their line styles (solid vs dotted) and the Display legend text;
  highlights keep their colour names in the panel and editor; the active rail tab is `aria-selected` plus the
  accent bar (shape); "I know this" is `aria-pressed` with a check icon when on.
- **Strings:** new strings in `apps/web/src/lib/i18n/messages/en.json` (sorted) via `t()` / `<Msg>`; no
  fixed-locale formatting, no literal `lang` (CJK text keeps `lang={textLang}`). Keys listed in "i18n keys".
- **Keyboard shortcuts preserved:** `b` (bookmark the paragraph in view), `h` (highlight the selection), `R`
  (show/hide all readings in smart mode), Escape (closes the top popup first, then the sheet / collapses nothing
  else), Shift+hover nesting, Arrow/Home/End in the rail tablist, Tab order text → panel → icon column. Each has a
  regression test (Task 13) — the existing `bookmarkKey`/`highlightKey`/`revealKey` unit tests stay unchanged.
- **Accessibility:** the existing live regions (bookmark announcement/alert, highlight live/alert) stay outside
  the rail so they are heard with the panel collapsed or the sheet closed; focus returns to the opener when the
  sheet closes (Sheet does this) and to the word's paragraph context when the lookup sheet closes; the rail
  column's focus rules on crossing the breakpoint stay (focus goes to the active tab or the top-bar button);
  forced colours as above; `prefers-reduced-motion`: the panel's open/close, the popup fade and the sheet slide
  use `--motion-*` (0ms under reduce).

## Rulings

- Ruling: the rail is five icon tabs (Contents, Bookmarks, Highlights, Words, Display) in a vertical tablist with
  tooltips — the design's icons at the right edge; tablist semantics are kept (not a toolbar of toggles) because
  exactly one panel shows and the existing keyboard model and tests are built on it — cost: none.
- Ruling: Contents and Display become rail tabs — the design lists them in the rail; today the chapter select and
  the Display disclosure sit above the text and push it down — cost: the chapter select moves one click away (the
  prev/next arrows stay at the chapter's end).
- Ruling: one breakpoint for the rail, the existing `RAIL_COLUMN_MIN_WIDTH` 1000px: column at or above, sheet
  below (the floating right-edge drawer goes) — the design's phone pattern is the top-bar button; one rule keeps
  tablets simple — cost: a 900px tablet gets a bottom sheet (max 40rem wide, centred) instead of a side drawer.
- Ruling: the lookup becomes a bottom sheet below the frame's phone breakpoint (the constant #99 exports; 640px if
  #99 exports none — then record it), not at 1000px — a 300px popup below the word fits comfortably on a tablet,
  a sheet only helps where the popup would cover the text — cost: two breakpoints in the reader (rail 1000, lookup
  phone).
- Ruling: the phone's rail button goes into the frame's phone top bar through the page-actions slot #99 provides
  (if it provides none: the reader's own sticky header row at the top of the page, right end, and a follow-up note
  for #99) — the design puts it in the top bar — cost: depends on #99's API.
- Ruling: the phone rail sheet is the shared modal `Sheet`; actions that leave the sheet's content (jump to a
  bookmark / highlight / chapter, edit a highlight, which opens the floating editor) close the sheet first, then act
  — a modal sheet makes the page inert, so the editor could not be used above it — cost: after editing, the person
  reopens the sheet to continue.
- Ruling: the lookup sheet shows the root frame only; Shift+hover nesting needs a mouse and keeps its popups —
  touch never nests today — cost: a narrow desktop window with a mouse gets a sheet and no nesting (the person can
  widen the window).
- Ruling: the popup keeps `placePopup`'s fallback (above the word when there is no room below) — the design says
  below, but a popup off-screen hides its buttons — cost: none.
- Ruling: word marks lose their tint layer and draw a 1.5px line (new solid `--accent`, learning dotted `--warn`)
  — the mockup's lighter marks; the line style carries the state in every theme and in forced colours — cost: the
  `docs/contracts/reader/README.md` sentence "each with a light tint" changes (a doc change, no fixture: the
  rule is presentation).
- Ruling: "new = … with pinyin/furigana above" in the design describes smart mode (readings shown for words not
  yet known); the default `readings: never` stays — changing a default changes what the feature does — cost: the
  default page shows underlines without readings until the person picks Smart in Display.
- Ruling: lookup results gain `levels` from the server (lowest level per scheme, the entry page's badge rule) —
  the design shows level chips and the popup has no other source; one batched query per lookup — cost: an API
  addition (documented, additive; old clients ignore it).
- Ruling: "Add to deck" stays one click to General (today's add button) with a separate "Choose a deck" menu
  button — the design shows one primary "Add to deck"; making it open a menu would add a step to the most common
  action — cost: two buttons where the mock draws one.
- Ruling: the deck menu uses `lib/ui/Menu` (roving focus, Escape returns focus) instead of the hand-made menu in
  `AddToStudyButtons` — one menu implementation — cost: `AddToStudyButtons.dom.test.ts` is the regression net
  (its names stay; a role query that changes is recorded as forced by the design).
- Ruling: no "12 min left" in the book line — nothing measures reading speed per book today; inventing an estimate
  is a feature — cost: the line is shorter than the mock.
- Ruling: the library page and source browser are not restyled here ("pages not mocked", #106) beyond what PART B
  already did — cost: none.
- Ruling: `features/reader/fonts.ts` is deleted and the reader calls `$lib/fonts/hanzi` directly (its own comment
  scheduled this for #102) — cost: none; `display-settings.json` decoding is unchanged.
