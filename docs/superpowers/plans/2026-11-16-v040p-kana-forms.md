# Kana display forms (issue #92) Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [x]`) syntax. Strictly test-first: write the test, run it,
> SEE IT FAIL, implement, see it pass. One commit per task.

**Goal:** Every surface that picks a Japanese word's display form uses one rule: a kana list form (starter
decks), then a first-sense `uk` → kana, then the best non-search-only written form, then the kana reading.
の shows as の, こと as こと, する as する; search-only forms are never a headword.

**Spec (binding, incl. Rulings):** `docs/superpowers/specs/2026-11-16-v040p-kana-forms-design.md`.

**Branch / worktree:** `feature/v040p-kana-forms` at `.claude/worktrees/kana-forms` (`<wt>`), from
`feature/v0.4.0-prep`. Parallel with items 1 and 3; shared files at most `docs/contracts/README.md` and the
wiki (textual conflicts only).
