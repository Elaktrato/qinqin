## The bug, on the shipped CC-CEDICT (greedy, reproduced first)

CC-CEDICT gives one character entry per character with every line's reading, in line order, and the segmenter showed
the first: 那 nā (the surname line), 着 zhāo, 得 dé, 打 dá, 看 kān. Greedy longest match merged reached words into
compounds outside the level list (这不｜是, 一个, 中国人, 明天见, 那是) and crossed word boundaries (我｜有时｜间,
学｜得很｜好, 我｜在教｜室).

## What

1. **`segment/zh.json`**: Chinese gets segmentation rules, so it is read on #348's lattice. The rules format grows
   optional keys (ja.json stays byte-identical, its results unchanged):
   - `costs.levelStep`, `costs.unlisted`: a token whose head entry is a direct member of an installed **word** level
     list of the language (HSK) costs `token + min(levelStep × level index, unlisted)`, any other `token + unlisted`;
   - `compounds: "parts"`: a token of two or more characters whose head is unlisted is no edge when its text can be
     read entirely by listed words and function words inside it (不是 → 不｜是, 中国人 → 中国｜人);
   - `functionReadings`: a function word is recognised by its lemma and its reading (CC-CEDICT has no parts of
     speech): 着 is a function word because its entry has the reading zhe; its match shows that reading;
   - `partFunctionWords`: the function words that count as a compound's part anywhere (得 in 得很); any other function
     word (地) only as the last part;
   - `readings`: a short table of common readings where CC-CEDICT's lines mislead (几 jǐ, 长 cháng, 没 méi, …).
2. **The reading of a match** (zh): the function reading; else the table; else the reading whose everyday senses have
   the most glosses (minor senses — surname, variant, "used in", archaic: the sense display rule — count nothing);
   ties to the earliest; else the first.
3. **The head** of an edge (several entries with one surface): a function word's entry, else the listed entry with the
   lowest level, else the ranking's first.
4. **Contract 39** `docs/contracts/segment/`: `zh.json`, `zh-cases.json` (CC-CEDICT lines, a word level list, texts
   with tokens, readings and function flags, with and without the list), README; Go and web decode it; CHANGELOG.
5. **Real data**: a `realdict` test on the shipped CC-CEDICT and `hsk-words`; long-chapter timing (zh Tatoeba, 5,000
   runes, full CC-CEDICT + HSK) before and after.

## Rulings

- Ruling: Chinese gets `zh.json` on #348's lattice, with optional keys in the same format 1 (`levelStep`, `unlisted`,
  `compounds`, `partFunctionWords`, `functionReadings`, `readings`), all absent from `ja.json` — the engine was built
  per language; absent keys are zero/empty, so `ja.json` stays byte-identical and Japanese reads exactly as before
  (checked token by token on the long chapter) — cost if wrong: a format 2 bump, no engine change.
- Ruling: **the common reading of a single character comes from CC-CEDICT's line content, not the level list or line
  order**: the reading whose everyday senses (not minor by the sense display rule: surname, variant, "used in",
  archaic) have the most glosses, ties to the earlier line; a function word shows its function reading; a short
  `readings` table (几 jǐ, 长 cháng, 雨 yǔ, 教 jiāo, 胖 pàng, 为 wèi, 没 méi, 重 zhòng) covers common characters where
  that rule misleads — CC-CEDICT merges a character's lines into one entry with every reading, and a level
  membership is per entry: the importer keeps no reading (HSK lists 那 nà, 得 de/dé/děi on one entry), so the level
  list cannot name the reading without a migration; no Chinese frequency pack is bundled; line order is what gave
  nā, zhāo, dé, dá. Measured on the 298 HSK characters with several readings: line order (first non-minor) misses
  109 of the HSK reading, the gloss count 70; of the misses at HSK 1–3 every one is a function word (handled) or in
  the table, except 子 (zǐ for the suffix zi, which lives inside words) — cost if wrong: a character outside the
  table shows a less common reading (zháo-like cases at HSK 4+); storing the listed reading on a membership
  (migration + importer) would let the list decide.
- Ruling: **a compound outside the learner's list whose parts are listed is split, not shown as one word made of known
  words** (`compounds: "parts"`): such an edge is dropped when listed words (and function words) inside it read its
  whole text — splitting needs no new payload field, and every client rule stays as it is: each part is its own match
  with its own entry, so word states, the reached check of a reading lesson and coverage all count the known parts;
  a "compound of known words" display would need a new match shape, a second word state and a coverage rule for it —
  cost if wrong: an idiomatic unlisted compound reads as its parts (一丁点 → 一｜丁｜点, 剩下 → 剩｜下, 那是 → 那｜是); the
  popup still finds the compound at the cursor (`/api/segment/at` is unchanged).
- Ruling: "listed" means a direct member of a live **word-unit** scheme of the language (`level_members.derived = 0`);
  derived character memberships and character schemes do not count — a character is derived from every listed word
  written with it, so counting derivations would make nearly every unlisted compound split into characters. The
  importer keeps one membership per entry at its lowest level, so a character listed as a word at HSK 2 but derived
  at HSK 1 (间 from 时间, 为 from 为什么) counts as unlisted — cost if wrong: such a character inside an unlisted
  compound does not split it (为上 in 为上这门课 stays one token; greedy did the same).
- Ruling: level costs `levelStep` 10 per level index, `unlisted` 80 (one step past HSK 7–9), on top of `token` 100;
  function words cost `token` only; `unmatched` 300 — the level step decides between two readings of equal token
  count (有｜时间 at HSK 1 + 1 over 有时｜间), `unlisted` keeps a listed word cheaper than any unlisted one and stays
  below a token, so the number of tokens still dominates; with no list installed every token pays `unlisted` and the
  costs reduce to the token count — cost if wrong: retune two numbers in `zh.json` and the fixtures.
- Ruling: function words are 的, 了, 着, 得, 地, 吗, 呢, 吧, 啊, 呀, 嘛, recognised by lemma **and** their function
  reading (着 zhe) on the entry — CC-CEDICT has no parts of speech; the reading guards against a homograph without
  it. 过 is left out (the verb guò is common on its own: 过马路), as are 们 (a suffix inside listed words) and 是 (a
  verb to learn) — cost if wrong: extend the list; a standalone 着 zháo or 地 dì ("the ground") is shown as the
  particle (no reading, no word state).
- Ruling: `partFunctionWords` (的, 了, 着, 得, 吗, 呢, 吧, 啊, 呀, 嘛) count as a compound's part anywhere; 地 only as
  the last part — CC-CEDICT has hundreds of unlisted nouns starting with 地 (地上, 地产) that 地 the particle would
  otherwise split, while compounds ending in it after a listed word (在地 in 在地上) are the particle's position — cost
  if wrong: an unlisted noun ending in 地 (山地) reads 山｜地 de.
- Ruling: the head of an edge with several entries is the function entry, else the listed one with the lowest level,
  else the ranking's first — the match's first entry decides its word state and reached check — cost if wrong:
  `entries` order differs from the lookup ranking for these surfaces only.
- Ruling: one batched read of the word levels per segmentation (`levels.WordLevels`, 500 ids a query), only for rules
  that use them — the levels package owns its SQL (record 0003) — cost if wrong: one more query per request.
- Ruling: no migration and no importer change — the bug is in the segmenter; changing which memberships are direct
  would move words between levels in the course fill (#221/#223) — cost if wrong: the table and gloss rule carry the
  reading choice until a later issue stores the listed reading.
