## Global constraints

- The rule text in the spec section "The rule (contract)" is authoritative; fixtures win over code. If
  a fixture value looks wrong, re-derive it from tzdb by hand and note it in the task report; never
  edit a fixture to match an implementation without that derivation.
- Stored `ts` format is `2006-01-02T15:04:05Z` (UTC, whole seconds); window bounds use exactly it.
- History JSON: `{"zone": string|null, "history": [{"zone": string, "from": string|null}]}`; `from` is
  RFC 3339 UTC seconds.
- Zone validation: 1–64 bytes, `^[A-Za-z0-9_+\-/]+$`, not `Local`/`Factory`/`posixrules`, no `posix/` or
  `right/` prefix, and loadable from Go's **embedded** tzdata (`time/tzdata`'s data via `tzdata`-only
  loading, e.g. `time.LoadLocationFromTZData` over the embedded zip, never the host zoneinfo).
- Error bodies of the new routes are JSON `{"error","message"}` (accounts convention, #64).
- Rule domain: instants from 1970-01-01 (earlier ones clamp).
- Web fixtures and source scans never use `node:fs` (no `@types/node`): fixtures are imported as JSON
  (`resolveJsonModule` is on), the source scan uses `import.meta.glob('/src/**/*.{ts,svelte}', { query:
  '?raw', import: 'default', eager: true })`.
- No user's zone or history is logged.

## Review Focus

1. **Monotone days.** The westward fixture (Tokyo → Los Angeles) must give one long 2026-11-11 and no
   repeated date, in Go and TS. Pinned in Tasks 2 and 6 by `day-of.json` / `day-start.json`.
2. **Skipped and gap dates.** Pacific/Apia 2011-12-30 has an empty window; America/Santiago 2024-09-08
   starts at 04:00Z. Pinned by the same fixtures and by `TestWindowsEmptyDay`.
3. **Past days never move.** A second `PUT` changes no cell before its `from`. Pinned in Task 5
   (`TestActivityZoneChangeKeepsPast`) and in the real-app check.
4. **Index use.** The day join must keep `idx_study_events_user_type_ts`; the existing large-log test
   (`server/internal/stats/large_test.go`) keeps its time bound. Pinned in Task 5.
5. **No forgotten UTC call site.** Task 10 adds a source-scan test; reviewers check its allow-list.
6. **Isolation.** User B never sees or changes A's history (Task 4).
