# v0.9.0 plan — courses, and everything around them (2026-11-26)

The owner's plan for milestone **"v0.9.0 — courses"** (GitHub milestone 8, 48 open issues on 2026-11-26). Every
open question in the issues was answered in planning; the answers are below and as an "Owner decisions
(2026-11-26, v0.9.0 planning)" comment on each issue concerned. **An agent can work through this milestone
without stopping for the owner.** If something new comes up that this plan and the issues don't settle, make the
call that best fits the decisions here, write it down as a ruling in the issue's plan, and carry on.

## 1. How the work runs

- **Integration branch `feature/v0.9.0`** from `develop` (at `2b95634f`, the v0.8.0 release, or later). One branch and one
  plan (`docs/superpowers/plans/`) per issue, tests first for logic, a `--no-ff` merge into `feature/v0.9.0` once CI
  is green on the state merged with the integration branch. A PR `feature/v0.9.0` → `develop` runs CI on the whole
  state; **merging it, tagging and releasing are the owner's call.** Alpha tags (`v0.9.0-alpha.N`) are fine at
  sensible points.
- **No separate patch release:** the bugs (#294, #283, #282, #296, #288) ship with v0.9.0.
- **Contracts:** each change to a shared rule goes into `docs/contracts/` with fixtures, a ContractVersion bump and a
  CHANGELOG entry, as in v0.8.0. Android gets everything through the web app in the shell.
- **Independent review:** once the milestone's work is in, one review of the whole branch by the strongest
  available model, then a fix wave, as in v0.8.0.
- **Handoff:** end with `docs/superpowers/handoffs/<date>-v090.md` in the v0.8.0 format (what shipped, what the
  review found, rulings, anything still pending, what wasn't checked by hand) and draft release notes in
  `docs/releases/v0.9.0.md`.
- **Hand checks** the owner does later. Note in the handoff what wasn't checked on a phone or in a browser; nothing
  waits for it.

## 2. Content review: teacher subagents, never the owner

Owner decision: written content is handled **like the grammar lessons**. It's reviewed by **native-language teacher
subagents in the target language**: several where possible, at higher reasoning, each acting as an experienced
teacher of that language. Their findings are applied before shipping. The owner reviews and corrects it later, at a
release state, as they go. **Nothing waits on the owner.**

This covers: the course skeletons and reading texts (#223), topic labels (#220, replacing "only reviewed labels
ship"), the graded readers (#231), the Starter lists (#275), the look-alike sets (#228), the Japanese counters table
(#179), the German and Japanese interface catalogues (#144, #145), and any example sentences or glosses an agent
writes. Keep each review's notes (who, what was changed) beside the content or in its PR, and mark the content
"reviewed by agents" where the app or docs show a review state.

## 3. Decisions that apply across issues

- **Drills framework** (one, shared): the conjugation trainer (#178), measure words and counters (#179), tone pairs
  (#180) and look-alike characters (#228) are **drills**. Each drill item (word × form family, noun, tone pair, set)
  gets its own spaced schedule (FSRS, derived from events like flashcards) and its own event type, outside the
  flashcard queue. They live in one Practice area with a "practise weakest" round. Build it once, with a contract,
  before the first drill. It uses the shared study core from #278 and counts in stats, EXP and goals.
- **Grammar** becomes events (#277) before grammar review (#181) and before courses use grammar lessons.
- **Hidden romanisation** (#284) is respected by every new screen in this milestone (drills, courses, sentence cards,
  the browser add-on).
- **Phone first:** every new screen is checked at 360 px with no horizontal scroll (the guard from #296).
