**Goal:** the app gets its frame. Desktop (≥ 720px): a window frame in `--chrome` with the page as a raised
`--panel` inset 8px with `--radius-large` corners; a top bar with the 勤 logo as the Home link (tooltip
"Home"), the section icons centred (Decks, Reader, plugin pages such as Journal and Grammar, Search, Stats),
icon-only with tooltips, active = accent icon + a small accent dot; on the right the workspace **flag** alone

a drawer from the inline-start edge with the workspace flags (tap to switch, + to add), the current workspace
named, the sections with icon + label (Home included), and the account at the bottom. The footer and the
bottom tab bar go. Plugin sections take their icon from their manifest (`icon`, fallback a generic icon).

## Accessibility (binding)

- **Skip link** stays the first focusable element on every page with a frame; it focuses `#main-content`.
  On the phone it is still first (before the menu button).
- **Landmarks:** one `<header>` (banner) holding the bar; one `<nav aria-label={t('nav.main')}>` visible at a
  time (desktop bar or drawer; the hidden one is `display: none`, so it is out of the tree); the drawer's nav
  has the same name; the panel is the content region (`div.content#main-content`, pages keep their own
  `<main>`); no `contentinfo` (the footer goes).
- **Focus order (desktop):** skip link → logo (Home) → sections in order → flag → avatar → page. **Phone:**
  skip link → menu button → flag → page. Opening the drawer moves focus to the current workspace's flag;
  closing returns it to the menu button.
- **Drawer:** a modal dialog (`aria-modal`, `aria-label={t('nav.drawer')}`), focus trapped (Tab wraps),
  Escape and the scrim close it, the page behind is inert; it closes itself on navigation (a section link,
  a workspace switch); `prefers-reduced-motion` → no slide.
- **Icon-only controls** (logo, section icons, flag, avatar, menu button) have an accessible name and a
  Tooltip on hover and keyboard focus (IconButton / Tooltip from #98). The current section has
  `aria-current="page"`; the dot is a shape cue in addition to the accent colour.
- **Menus** use `lib/ui/Menu` (APG menu button): workspace items are `menuitemradio` with `aria-checked`
  (a check icon as the non-colour cue); account items are `menuitem`s/links.
- **Forced colours:** the active dot and drawer bar use `Highlight`; the panel edge gets a `CanvasText`
  1px outline (fills vanish).
- `scroll-padding-bottom` for the bottom bar goes with the bar; `--bottom-bar-height` and its three callers
  (`CardManager.svelte`, `features/reader/ReaderRail.svelte`, `routes/study/scheduling/+page.svelte`) are
  cleaned up (no bar any more).

## Rulings

- Ruling: section order is core features (Decks, Reader), then plugin nav pages in the user's plugin order
  (Journal, Grammar), then Search, then Stats — the mockup shows Study, Reader, Journal, Search, Stats, i.e.
  "doing" sections first and the tools last — cost: users used to Search first look one slot further.
- Ruling: the flashcards section keeps its catalogue label "Decks" (`features.flashcards.title`) with the
  `study` icon; the mockup's "Study" is a placeholder word and renaming is not this item's job — cost: the
  tooltip reads "Decks", not "Study".
- Ruling: Stats moves from the footer into the bar (design §9) — the existing tests "puts Stats in the
  footer links, not in the main navigation" and "marks the footer Stats link current on stats pages" in
  `routes/layout.dom.test.ts` change to assert Stats in the main nav (forced by the design; recorded in the
  Execution record) — cost: none.
- Ruling: the footer is removed; **Sources** (credits and licences, which must stay reachable) moves into the
  account menu and the drawer's account area, the app-name/version line goes (the Sources page shows the
  build) — the design takes Settings out of the footer and mocks no footer — cost: Sources is one click
  deeper.
- Ruling: the account menu's Theme item is a drill-in level inside the same popup ("Theme · Latte ›" →
  a "Back" item, the themes of the painted slot as radio items, "Appearance settings…") instead of a nested
  flyout menu or an inline list — it matches the mock's single row, works the same on the phone and needs no
  submenu pattern — cost: `MenuItem` gains `keepOpen`; Escape at the theme level closes the whole menu (the
  Menu contract), ArrowLeft/"Back" returns one level.
- Ruling: `ThemeSwitch.svelte` is retired; its choices and save logic move into `ThemeMenuItems.svelte`
  (used by the account menu) and `ThemeSwitch.dom.test.ts` becomes `ThemeMenuItems.dom.test.ts` with the same
  cases (picking writes the painted slot, keeps an offered accent, shows the error line, lists the painted
  slot's themes) — one implementation, one test net — cost: the #98 note "ThemeSwitch tests unchanged" ends
  here.
- Ruling: the header `WorkspacePicker.svelte` (listbox + inline create form) is retired; the flag opens
  `WorkspaceMenu` (Menu with radio items + "Manage workspaces" → `/settings?tab=workspaces`); creating a
  workspace happens in Settings (and on Home when there are none: `WorkspaceCreateForm` stays) — design §9 —
  cost: creating one is a click further away.
- Ruling: the drawer's "+" is a link to `/settings?tab=workspaces#new-workspace` (the create form's heading,
  focused by Settings on load) — no create form inside the drawer — cost: one page change.
- Ruling: desktop/phone is a CSS switch at 720px (the old bottom-bar breakpoint), both bars rendered —
  no JS media query, so no layout jump on first paint and it follows zoom — cost: the hidden bar's markup
  exists (`display: none`, not in the accessibility tree); dom tests scope queries to the visible bar's
  `data-frame` element.
- Ruling: the phone bar's title is the current section's label (Home's label "Home" on `/`, not the mock's
  "Today"), with `setFrameTitle()` for a page that wants something more specific — pages need not all publish
  titles now; later items (#104 entry) can — cost: an entry page reads "Search" on the phone until #104.
- Ruling: plugin icons come from a new optional manifest field `icon` (a name from the app's icon set:
  the names of `lib/ui/icons/lucide.ts`); Go validates only its form (`^[a-z][a-z0-9-]{0,31}$`), clients map
  unknown names to the generic `plugin` icon — Android has its own icon set with the same names — cost: a
  typo in a manifest shows the generic icon silently (the web test of the built-ins catches ours).
- Ruling: restricted sessions (forced password change, MFA enrolment) get the bar with the logo and the
  account menu holding only Sign out (no sections, no flag); signed-out open pages (Sources) get the bar with
  the logo (→ `/login`) and a "Sign in" link — the same reach as today — cost: none.
- Ruling: the notice region, UpdateBanner, OfflineBanner and the workspace load error render at the top of
  the panel (inside the raised surface, above the page), not in the chrome — they are about the page's
  content — cost: none.

**How later pages use the frame (#102 reader, #104 search/entry, and any page).**
- `import { setFrameTitle, setPageActions } from '$lib/frame/pageFrame.svelte'`. Call both **while the page
  component initialises** (they create an `$effect`): `setFrameTitle(() => entry.written)` (a function keeps it
  reactive; a string is fine for a fixed title) and `setPageActions(actions)` with `{#snippet actions()}
  <IconButton label=… icon=… onclick=… />{/snippet}`. Both live exactly as long as the calling component: they
  follow its reactive values, and go away when it is destroyed (navigating elsewhere); navigating within the same
  page (new params) keeps them up to date. The last caller owns the slot; an old page's teardown never clears a
  newer page's title (owner check). The title falls back to the current section's label, else "Home".
- The actions render **only in the phone bar** (between the title and the flag; focus order menu button →
  actions → flag → page). On desktop the page shows its own controls; hide them below the breakpoint with CSS.
  Use IconButtons (named, with a tooltip); keep to one or two.
- `import { FRAME_PHONE_BREAKPOINT, PHONE_MAX_WIDTH, PHONE_MEDIA_QUERY } from '$lib/frame/breakpoint'`
  (720 / 719.98 / `'(max-width: 719.98px)'`) for `matchMedia` or documentation; CSS writes
  `@media (max-width: 719.98px)` (the layout does; `pageFrame.test.ts` holds the layout to the constant).
- The reader's rail button: `setPageActions` with the IconButton that opens its Sheet. The entry page:
