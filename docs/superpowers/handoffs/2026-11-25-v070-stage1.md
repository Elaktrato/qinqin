## 2. What the emulator proved (CI job, Android 14, WebView Chromium 113)

- First-run screen → server address → the web app loads; the Capacitor bridge is present on that origin.
- Service worker registers, activates and controls the page (at `http://localhost:8085/` through `adb reverse`; a
  LAN IP over http is not a secure context, so no service worker there — documented in the wiki).
- Offline start from the service worker cache works (0.8–1.4 s, no error screen).
- Airplane-mode study session: 4 cards offline, outbox of 4 kept across an offline restart, drained in 2.1 s
  once online; the server holds exactly 4 review events (4 distinct ids), still 4 after two more restarts.
- Defects the emulator found in #34 (fixed): a blank page (`App.addListener` returns a handle, not a promise) and
  `navigator.onLine` never changing (missing `ACCESS_NETWORK_STATE`).

## 3. Storage numbers and decisions (#35; full text in the design doc)

- Quota 4,981,238,169 bytes (~60 % of the 8.1 GB data partition); usage after preparing 4 cards ≈ 5.0 MB; 1 GiB
  written to the Cache API without error; entries survived force-stop and `pm trim-caches`.
- `persisted()`/`persist()` are both false in the WebView; nothing depends on it.
- The web app downloads none of the big packs (dictionaries 36 MB, strokes 32 MB, Kanji alive audio ~69 MB stay
  on the server), so offline needs 5–20 MB.
- **No blocker found** in the WebView for offline start or storage. The writing pad on touch was **not** tested.

## 4. Rulings (the full list with costs is in the plans and design docs)

- Native file storage: **no** — 5–20 MB against a 5 GB quota. Cost if wrong: a bridge-served package store later.
- Token storage: **stays in `localStorage`** — WebView storage is app-private, `allowBackup` is off, and Keystore
  would not stop a script on the page. Cost if wrong: a secure-storage plugin and a bridge feature.
- The review outbox moves to **IndexedDB with write-ahead** (a force-stop within ~5 s after grading used to lose
  reviews shown as saved; `pagehide` cannot fix a kill). No contract bump (storage is the client's own).
- No `@capacitor/*` import in `apps/web`; `lib/native` talks to the injected `window.Capacitor` (a repo test
  enforces this). No status-bar or keyboard plugin (SDK 36: core `SystemBars` covers it).
- Runtime server address: the activity is recreated on every switch (Capacitor fixes allowed origins at bridge
  creation). Only the origin is kept (the app uses absolute `/api` paths).
- Plain http allowed only for private hosts (checked in JS **and** Java); single-label hosts and `*.local` stay accepted.
- Bridge level 1, feature `status-bar`; the server lists it, so contract version is **2**.
- Documentation is CC BY 4.0; UI strings and contract fixtures are MIT; earlier published copies keep their old licences.
- The emulator job runs only on path-filtered PRs and by hand (≈ 8 min; a bit flaky — re-run once before trusting a failure).
- This machine cannot run an emulator (`/dev/kvm` not accessible to the user, RAM tight); no sudo was used to change that.

## 5. What the owner must check on a real phone

1. Install the debug APK (`apps/android`, steps in `docs/wiki/Android.md`), enter your server (HTTPS), sign in.
2. Back button/gesture: a sheet, menu, dialog, the reader lookup popup, then history, then leaving.
3. Status/navigation bar colours in qinqin Day and Night; safe areas; the keyboard on a typing card.
4. Writing pad and tone pad on touch (not tested by the emulator job).
5. Airplane mode: open the app, study a few cards, restart the app, come back online.
6. "Change server" in the account menu and the launcher shortcut; a server that is down vs. one that is not qinqin.
7. Plain http to a LAN address shows the warning; no offline start over plain http (by design).
8. Force-stop right after grading a card, reopen online: the reviews should still arrive (IndexedDB outbox).

Not verified by any run: the not-qinqin re-check, the launcher shortcut and the old-WebView guard (JVM tests only);
eviction under real low-disk pressure; a foreign origin lacking the bridge; the reader and dictionary offline (the
web app is online-only for those).
