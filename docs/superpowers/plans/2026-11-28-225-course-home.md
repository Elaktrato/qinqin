## What

- **Counting** (contract `courses/counting.json`): course work counts in the heatmap, goals, the weekly summary, EXP,
  the streak and days active, the way grammar runs (#277) and drill answers do.
- **Course milestones** in the existing milestone system (`milestones/catalogue.json` appended, `milestones/course.json`):
  the first lesson, each unit, each section, each script, character and word counts, and graduation. Shown once on
  Home or Stats → Week, then in the history.
- **Home widget "Continue course"** (`courses/home.json`): the workspace's course, its next lesson one tap away, the
  progress; in the default Home layout.
- **Onboarding**: a fresh workspace whose language has a course gets one "How would you like to start?" card on Home:
  "I'm new to <language>" (start the course, and add the Starter words with Starter mode) or "I know some already"
  (Find your place, or say which levels you know, #74).
- **Leaving the course**: the graduation milestone, and on the roadmap (and the widget) a short guide to free study.

## Rulings

Format: `Ruling: <what> — <why> — <cost if wrong>`.

### Counting

1. Ruling: **what counts is a course "step": a finished lesson that is not a grammar lesson, a unit test, a section
   exam** (`courseItemsOf`; `lesson-started` and `placement` count nowhere) — a course grammar lesson already records a
   `grammar` run (#222 ruling 20), which counts for activity, EXP and the streak on its own; counting it again as a
   course step would give one lesson two heatmap points and 40 EXP — cost if wrong: a learner's "course lessons" goal
   does not move on a grammar lesson of the course (its "grammar lessons" goal does).
2. Ruling: **activity: one point per step per learner day** (rule `course`, feature `courses`, `item: "course"`: a
   `distinct` rule whose value is the step's identity: `lesson <course> <unit> <lesson>`, `unit-test <course> <unit>`,
   `section-exam <course> <section>`) — #277's "once per lesson per day"; a unit test retaken after a fail the same day
   is one point — cost if wrong: none.
3. Ruling: **the distinct value is a named item rule (`item`), not a generic multi-field key** — the step's identity
   depends on its kind; a generic "fields + filter" rule language would be machinery for one rule; the item is a fixed
   SQL expression in Go and a fixed function in TS, both pinned by `counting.json` — cost if wrong: a second rule with
   a composite key adds a second named item.
4. Ruling: **the server's item reads members by JSON type only** (text `course`, `unit`, `lesson`, `section`; the kind
   one of the three), not the full #221 parse — the activity rules never fully validate payloads (grammar's `point`
   is read the same way) — cost if wrong: a hand-made malformed event with text members scores a point.
5. Ruling: **EXP: 20 per step** (`COURSE_STEP_XP`), whatever the score, also a failed test; no daily bonus (it stays a
   review bonus) — the grammar run's 20 (#277); a test is effort as much as a lesson; "nothing takes away" (design §2)
   — cost if wrong: retaking a failed unit test earns EXP each time (as repeating a grammar lesson does).
6. Ruling: **the streak and days active count a learner day with a step**, everywhere the streak is shown and in the
   milestones' `streak` and `days-active` families — one streak rule across the app (#277, drills) — cost: none.
7. Ruling: **the goal needs no new metric**: `activity:course` follows from the activity source; its words are "Course
   lessons" / "{n} course lessons" (a test counts as a lesson there) — cost if wrong: a test is called a lesson in the
   goal line.
8. Ruling: **the weekly summary shows course progress through what it already lists**: the activity row "Course
   lessons" with its comparison, and the week's milestones (units, sections, words reached that week) — the summary is
   built from activity rows and milestone items; a separate course block would duplicate both — cost if wrong: no
   "next lesson" line in the week view (Home's widget has it).

### Milestones

9. Ruling: **seven families, appended after `level-complete`, following the `courses` switch** (`source: "course"`):
   `course-started:<course>` (the first finished lesson), `course-unit:<course>:<unit>`,
   `course-section:<course>:<section>`, `course-script:<course>:<script>`, `course-characters:<course>:<n>` (100, 250,
   500, 1000), `course-words:<course>:<n>` (50, 100, 250, 500, 1000, 1500, 2000, 3000, the roadmap's marks, #222
   ruling 26) and `course-graduated:<course>` — the issue's list; ids carry the course id because a language may have
   several courses (#221 ruling 3), and pack, unit and section ids contain no `:` — cost if wrong: ids are never
   renamed (catalogue rule), so a family we regret stays.
10. Ruling: **a unit's milestone needs the unit's own work**: reached at the event that makes the unit done when that
    event is the unit's own passed unit test (early or not) or, for a unit without a test, the last of its lessons;
    units done by a skip (a later unit test, a section exam, a placement) get none — a skip of twenty units is not
    twenty achievements, the section milestone covers it — cost if wrong: a learner who tested out of a unit early
    still gets that unit; the units before it do not.
11. Ruling: **sections, scripts, characters, words and graduation count every done unit, skipped ones included**,
    reached at the event that completes them, whatever it is (a placement too) — design §7: skipped words "count
    towards word-count milestones as known words"; the roadmap already counts them reached (#222); a passed section
    exam is an achievement — cost if wrong: placement into ≈ HSK 3 shows "≈ HSK 1 done", "≈ HSK 2 done" and "500
    words" at once (one summary card).
12. Ruling: **a script milestone is reached when every unit naming the script (`scripts`) is done; characters count the
    `characters` of done units; words count met words plus the words of skipped units** (the roadmap's "reached") —
    the skeleton puts "all hiragana" at the end of the hiragana unit and "the first 100 hanzi" inside ≈ HSK 1 (#223
    ruling 8); done units are what the path shows — cost if wrong: a learner who finished a unit's script lesson but
    not its test does not yet have its characters.
13. Ruling: **the course replay is shared with the derivation** (`CourseReplay` in `studycore/courseProgress.ts`, used by
    `deriveCourseState` and the milestones) — two copies of "passed, skipped, done" would drift; `derive.json` and
    `changes.json` still pin it — cost: none.
14. Ruling: **course milestones are computed for the workspace's course** (the roadmap's: the device's pick, else the
    first by id), from the held course (session or device copy), fetched on Home and Week only when the workspace has
    course events, and only while `courses` is on — a client cannot title or derive a course it does not hold; a
    workspace without course events reaches nothing — cost if wrong: milestones of a second course appear only while it
    is the chosen one; their seen rows stay.
15. Ruling: **titles name the course's own words** ("Unit done: Hello", "Section done: ≈ HSK 1", "Hiragana complete",
    "100 course characters", "250 course words", "First course lesson", "Course complete: Chinese"); an id whose
    course, unit, section or script the client cannot name is left out of the history (as a level no longer installed)
    — no free text in ids; the levels rule — cost if wrong: a course uninstalled from the server hides its milestones
    from the history (seen rows kept).
16. Ruling: **Home computes the course families too** (they are not "replay" families: one pass over the course events
    and the held course) — the card "Unit done" belongs where the learner comes back after a lesson — cost: Home reads
    the course list and course once per session (held afterwards).

### Home widget

17. Ruling: **one widget `course-continue`** (owner `courses`, wide, Home only) **first in the default layout** — design
    §8 "the next lesson one tap away"; #222 left the bar pins unchanged because this widget is the entry — cost if
    wrong: a stored layout never changes (settings rule), so only new users and users without a stored layout get it;
    others add it in Settings → Layout.
18. Ruling: **with no course for the workspace's language the widget renders nothing** (no card, its slot hidden), and
    nothing while the course list is first loading — a default widget that says "no course for German" on every Home
    visit is noise — cost if wrong: a learner who expects the widget sees no hint why it is gone (Courses still says
    so).
19. Ruling: **the widget's model** (`courses/home.json`): `start` (nothing done yet), `continue` (a next step), `done`
    (graduated); the next step's lesson id and link (the roadmap's `next`), the unit and section, units done of all,
    words reached of all — a pure function over the filled course and the derived state, pinned so Android shows the
    same — cost: none.
20. Ruling: **no widget on Stats** — Stats shows numbers; the course's numbers are the activity row and milestones —
    cost: none.

### Onboarding and graduation

21. Ruling: **onboarding is a Home card for a fresh workspace, not a step in the creation form** — the form is used in
    three places (header picker, Settings, the empty state) and answers with Home or the current page; Home already
    holds the fresh-workspace offers (Starter, placement) with the same "brand new" test (no card, no known mark); the
    card is what the learner sees right after creating a workspace from the empty state — cost if wrong: a workspace
    created from Settings meets the card on its first Home visit, not in Settings.
22. Ruling: **with a course for the language (and `courses` on), one card replaces the Starter and placement offers**:
    "I'm new to <language>" → Start the course (the roadmap's first lesson) and Add the Starter words (Starter mode,
    #214/#275, when the server has a set and the mode is off); "I know some already" → Find your place (the course
    placement, #224) and "Tell us which levels you know" (#74); Not now (this device). Without a course, the old offers
    stay — the issue's two paths; three cards for one question would compete — cost if wrong: a learner who dismisses
    the card loses the Starter and placement offers too on that device (both stay in Settings).
23. Ruling: **the card shows while the workspace has no card, no known mark and no course event** — the offers' test
    plus "has not started the course" — cost: none.
24. Ruling: **graduation shows on the roadmap when the course is done** (no unit left): "You finished the course", what
    comes next as four links (Decks, a level session, the Reader, Grammar); the widget's `done` state links to it —
    the issue's "short guide to free study"; UI strings, not course content — cost if wrong: the guide is short (four
    lines), no teacher review needed.
25. Ruling: **the level session link is Study → a level** (`/study`), not a specific deck — level decks exist per
    installed scheme; the study page lists them — cost: one more tap.
