# v0.11.0 plan — community, administration and security (2026-11-27)

The owner's plan for milestone **"v0.11.0 — community and administration"** (GitHub milestone 10, 33 open issues on
2026-11-27). Every open question was answered in planning; the answers are below and as an "Owner decisions
(2026-11-27, v0.11.0 planning)" comment on each issue concerned. **An agent can work through this milestone without
stopping for the owner.** If something new comes up that this plan and the issues don't settle, make the call that
best fits the decisions here, write it down as a ruling in the issue's plan, and carry on. **When in doubt, choose
the more private and the more secure option.**

**Starts after v0.10.0** is merged into `develop` (its plan: `docs/superpowers/plans/2026-11-27-v0.10.0-plan.md`).

## 1. How the work runs

The same as v0.9.0 and v0.10.0:

- **Integration branch `feature/v0.11.0`** from `develop` after the v0.10.0 merge. One branch and one plan per issue,
  tests first for logic, `--no-ff` merges once CI is green on the merged state. A PR `feature/v0.11.0` → `develop`
  runs CI on the whole state; merging, tagging and releasing are the owner's call.
- **Contracts** with fixtures, a ContractVersion bump and a CHANGELOG entry for every shared rule.
- **New interface text** gets its `de` and `ja` translations in the same PR, reviewed by teacher subagents.
- **Cloud environment and the local follow-up:** never fake a step; what needs the owner's machine goes on the local
  follow-up list in the handoff.
- **Handoff** in `docs/superpowers/handoffs/<date>-v0110.md` and draft release notes in `docs/releases/v0.11.0.md`.
- **Phone first** and **hidden romanisation respected** on every new screen.

## 2. Security first and throughout (tracker #331)

- **First, before the new features:** #323 (the permission table and the route-walking authorization test) and #324
  (the shared upload intake and fuzzing). Everything after is built on them.
- **Alongside:** #325 (accounts and sessions), #326 (CSP and headers), #327 (supply chain), #328 (secrets).
- **With the social features:** #329 (block, report, rate limits, moderation).
- **Last, after everything else:** #330 (the independent review by several focused reviewers on the strongest
  model, from a written threat model; `SECURITY.md`; the hardening guide).
- **Rules for every PR in the milestone:** new routes go into the permission table in the same PR; new uploads use
  the shared intake; security fixes come with a regression test; a finding that can't be fixed in time is written
  down with its severity and a plan.

## 3. Per-issue answers (details in each issue's comment)

| Issue | Answer |
|---|---|
| #313 groups | Several group admins per group; members may leave unless the admin locks the group; group admins invite people without an account only if the server admin allows it. The group admin role sits below the server admin (see the issue for what it can and can't do). |
| #314 defaults | A default never overwrites a user's own choice; precedence: user, groups in join order, server, app. |
| #315 overview | Numbers only; group admins see their groups. |
| #316 passwords | At least 12 characters with at least one number, one uppercase, one lowercase and one special character, plus the common-password check (MIT-licensed list); no expiry by default; the admin may raise the length, not lower the rules. |
| #317 files | Quotas off by default; admins see file metadata only. |
| #318 dictionaries | Server, group and personal scopes; personal dictionaries are private even from admins (metadata only). |
| #319 permissions | Granted if any group allows it, unless another group explicitly denies it; group admins can only narrow. |
| #187 classes | A class is a group, the teacher its group admin; assignments (decks, course units, grammar lessons, texts) with optional due dates; "Assigned to me"; progress numbers and completion only. |
| #236 friends | Only people who share a group, or by exact user name or email; shared goal included; the admin can switch it off. |
| #59 journal sharing | Chosen people or a group; peer corrections in the AI review's annotation shape; no photos unless included; notifications through the reminder channels. |
| #142 shared decks | On the server plus a downloadable deck file; publishing by group permission, optional approval (off); updates merge by card, keep local edits, flag removed cards; user content in its own table; missing entries skipped with a report. |
| #332 shared mnemonics | Anonymous posting allowed; vote counts visible. |
| #333 corrections | Reviewed by admins or group admins; a shared correction layer that survives pack updates. |
| #334 challenges | Per-person targets, across workspaces; created by group admins, and by members if the group allows it. |
| #335 activity feed | Milestones only, opt-in per kind; one reaction, no comments. |
| #336 deck ratings | Only importers rate; one rating per user. |
| #322 shared books | Shared highlights off by default. |
| #337 single sign-on | Generic OIDC and account linking now; GitHub, Discord and X adapters later (#343); no Apple. |
| #321 approval queue | As written (pending accounts expire after 30 days). |
| #326 CSP | Never inline scripts; `unsafe-inline` for styles only if Svelte requires it; HSTS when the public URL is https. |
| #327 supply chain | Dependabot and Trivy. |
| #328 secrets | Access tokens expire after 90 days by default. |
| #341 inactive accounts | Off by default; suggested timeline when switched on: warn at 11 months, delete at 12. |
| #320, #338, #340 | As written. |

## 4. Build order

1. **Security foundations:** #323, #324; then #325, #326, #327, #328 alongside the next phases.
2. **Groups and roles:** #313 → #319 → #314; #316 (passwords and bulk resets), #321 (approval queue), #337 (OIDC
   and linking).
3. **Administration:** #315 (user overview), #317 (files and quotas), #318 (dictionary scopes), #338 (dashboard),
   #320 (announcements), #340 (maintenance mode), #341 (inactive accounts).
4. **Community:** #329 (safety) first, then #236 (friends), #142 (shared decks, closing #140) → #336 (ratings),
   #59 (journal sharing), #322 (shared books), #332 (shared mnemonics), #333 (corrections), #187 (classes), #334
   (challenges), #335 (activity feed).
5. **The independent security review (#330),** its fixes, then the handoff and release notes.

## 5. Local follow-up

1. OIDC sign-in against a real provider (for example Authentik or Google) with a public HTTPS address (#337).
2. The CSP and headers in the Android shell and with the service worker on a phone (#326).
3. Email flows end to end with a real mail server: bulk resets, approvals, inactive-account warnings (#316, #321,
   #341).
4. A Trivy scan and a full Docker build locally if CI can't (#327).
5. The usual hand checks on a phone and in a browser, with several test accounts in groups.

## 6. Not in v0.11.0

The GitHub, Discord and X adapters (#343), instance branding and legal pages (#339), admin-provided AI access (#342),
federation between servers, store publishing.
