**Architecture.**
- `apps/web/src/lib/stats/summary.ts` (new, pure) — `summaryNumbers(input)` → `{streak, wordsKnown, recall:
  {share: number | null, base: number}, studiedSeconds}` and `reviewsPerDay(input)` → `{day, count, today}[]`
  (30 learner days ending today). Every figure reuses an existing definition: streak = `dailyStreak` of
  `lib/study/exp.ts` (what the flashcards widget shows); words known = entries `known` by `lib/study/known.ts`
  (`knownIndex` + the familiarity predicate: a live known mark or a live vocab card at `MASTERY_THRESHOLD`);
  recall = the decks page's overall 30-day figure (`deckNumbers` with `deckId: null`, `RETENTION_MIN_REVIEWS`
  floor) — no second definition; studied this month = the sum of `lib/goals/amounts.ts` `studySeconds` over the
  learner days of the current calendar month (the `flashcards:studyTime` goal metric and the weekly `studyTime`
  row use the same amounts). Rules and fixture: `docs/contracts/stats/` (new folder).
- `apps/web/src/lib/stats/order.ts` (new, pure) — `STATS_ORDER` and `statsOrder(widgets)`: the design's default
  arrangement first (`summary-numbers`, `word-states`, `flashcards-summary`, `reviews-per-day`,
  `activity-heatmap`, `character-map-summary`, `reading-time`), every other widget after them in registry order
  (plugins keep appearing; the surface contract is untouched). `routes/stats/+page.svelte` calls
  `placeWidgets(statsOrder(…))`.
- Widgets (core, `lib/widgets/`): `SummaryWidget.svelte` (`summary-numbers`, size `wide`, surfaces
  `['stats', 'home']`, four `Stat`s from `$lib/ui`) and `ReviewsPerDayWidget.svelte` (`reviews-per-day`, size
  `wide`, surfaces `['stats', 'home']`, a 30-bar chart drawn with plain elements, an accessible list). Both read
  `loadStudyHistory` (cached; the flashcards widget already loads it) and `onStudyWrite` / `onContextStale` like
  the flashcards widget; neither is in the default home layout.
- `apps/web/src/lib/ui/Select.svelte` (new base component, the one #106 needs too): a native `<select>` drawn as
  an underline, the `Field` API (`label`, `bind:value`, `hint`, `error`, `hideLabel`, `options: {value,
  label}[]`, `…rest`), dom test, gallery entry, one line in `docs/contracts/themes/README.md` "Design rules and
  base components".
- Stats layout `routes/stats/+layout.svelte`: the base `Tabs` in its **route** form (`<nav>` of links,
  `aria-current="page"`), `data-sveltekit-keepfocus` / `noscroll` kept; the h1 stays in the outline.

- Stats tabs: `<nav aria-label={t('stats.tabsLabel')}>` of links, the current one `aria-current="page"`
  (the base Tabs route form; links that navigate are not ARIA tabs). Focus stays on the link after navigation
  (`keepfocus`); the panel is a region named by the current tab; the Characters tab still exists only for Han
  languages, and a direct visit elsewhere keeps its note.
- Summary widget: each `Stat` reads label then value ("Day streak, 23"); a recall below the floor reads "Recall,
  last 30 days: shown after 10 repeat reviews" (no bare dash).
- Reviews per day and the paired bars: the bars are `aria-hidden`; a visually hidden list carries each day
  ("Mon 16 Nov: 21 reviews, today"; "Monday: 42 points this week, 30 last week"); a one-line visible summary
  above the chart; each bar column has a `title` tooltip with the same text.
- Week arrows: `IconButton`s named "Previous week" / "Next week" with tooltips; at a limit the arrow is a
  disabled button (not removed), so the layout does not jump and the limit is announced as unavailable; the week
  heading keeps `aria-live="polite"`.
- Map: cells keep their roving focus, accessible names and tooltip; the legend is a list of words with
  decorative swatches; the stage filter buttons keep `aria-pressed`.
- Forced colours: bars draw as `CanvasText` outlines (this week solid, last week dashed — a shape cue); today's
  bar gets a `Highlight` outline; mastery cells use border styles per stage (not started dotted, fresh dashed,
  learning solid 1px, mature solid 2px, learned double 3px); the cell text stays `CanvasText`.
- Reduced motion: no new animation.

## Rulings

- Ruling: "reviews per day, last 30 days" is a **second new core widget** (`reviews-per-day`), not part of the
  summary widget — the design names one new widget for the four numbers and lists the reviews chart among the
  restyled contents, but no existing widget draws it; as its own widget it keeps the mock's order (numbers,
  cards by state and level, then reviews per day) and can be picked for Home — cost: two new widgets instead of
  one; merging them later is a registry change.
- Ruling: Stats gets a fixed default arrangement (`statsOrder`) instead of "core first, then features, then
  plugins" — the mock shows the design's order and registry order would put the core reviews chart before the
  feature widgets — cost: a plugin widget always comes after the default seven (as today it comes after core
  and features).
- Ruling: both new widgets are owner `core` though their numbers come from flashcards data — the design says
  "core summary widget"; with flashcards switched off they show `stats.summary.noFlashcards` (summary) or are
  left out by an empty state (reviews per day says "No reviews in the last 30 days") — cost: a core widget
  depends on a core feature's data (the milestones already do).
- Ruling: "words known" = entries `known` by the one known predicate (`lib/study/known.ts`: a live known mark or
  a live vocab card at the mastery threshold), not the decks page's "Mastered" (cards only) — the reader and the
  starter decks use the same predicate, so the number matches what the reader underlines — cost: it can be
  higher than "Mastered" on the decks page (marks count); the wiki says why.
- Ruling: "studied this month" = flashcards study time (`studySeconds`, the `flashcards:studyTime` goal metric
  and the weekly "Study time" row) over the learner days of the current calendar month; reading time stays in
  its own widget — one definition of "studied" across goal, week and Stats — cost: a learner who only reads
  sees 0 here (the reading widget sits below).
- Ruling: recall = the decks page's overall 30-day figure (`deckNumbers({deckId: null})`), and the decks page's
  label changes to "Recall, last 30 days" — design §10 renames the number; one number keeps one name — cost: a
  wiki line and a value change in the catalogue.
- Ruling: Stats → Overview keeps the **garden** heatmap; the person's Home layout choice (#100) is not followed
  here — the design's Stats mock shows no heatmap choice and the 13-week view is the long view Stats is for —
  cost: none (Settings → Home says the choice is for Home).
- Ruling: the stats tabs become the base `Tabs` route form (`<nav>`, links, `aria-current`) instead of today's
  `role="tablist"` links with manual activation — the base plan's ruling for exactly these tabs (links that
  navigate are not ARIA tabs); the heavy map is not loaded by arrowing past it because arrow keys no longer move
  between links — cost: the layout's `role="tab"` tests change (forced by the design; listed in the Execution
  record); `tabKeyTarget` in `lib/statsTabs.ts` is deleted with its test if nothing else uses it.
- Ruling: the "Stats" h1 stays visible above the tabs at `--font-size-l`, weight 600 — the mock's desktop panel
  starts at the tabs, but every page keeps its h1 (frame plan) and the phone bar shows the title too; hiding it
  only on desktop would need a frame-wide rule — cost: one line more than the mock on desktop.
- Ruling: the paired bars measure each day's **activity points** (`WeekDay.points`, the heatmap's measure,
  covering every activity type) — the mock does not name the measure and points are what "a day's study" means
  everywhere else; last week's bars cover all seven days of the previous week while the four numbers keep the
  contract's same-days comparison window — cost: on a Wednesday the bars show last week's Thursday–Sunday,
  which the numbers do not count (the legend says "last week", not "compared").
- Ruling: `previousDays` is added to `weekSummary` (and its fixture) rather than computed in the component —
  the day states (vacation, skipped, upcoming) follow the contract's rules and Android needs the same — cost:
  the fixture's `expect` objects grow.
- Ruling: the four Week numbers are reviews, new cards, study time and journal entries (the mock's four); when a
  row is absent (no journal plugin, flashcards off) the next row in the summary order takes its place (reading,
  then the first `activity:*`); every other row (days active, streak, mature, characters, goal, reading, other
  activity types) stays in a hairline list "More this week" below the bars — nothing the week shows today is
  dropped — cost: the page is longer than the mock.
- Ruling: `WeekStrip` stays for the home widget (compact); on the Week page its per-day state marks (✓ · V … —)
  move under the bar columns with the weekday, so vacation / skipped / upcoming remain visible without colour —
  cost: two day renderings exist (strip and bars).
- Ruling: Week arrows at a limit are disabled buttons instead of missing links — the mock shows a disabled "next"
  and a stable header — cost: a disabled control in the tab order is skipped (native `disabled`), its tooltip is
  not reachable by keyboard there; the name says it.
- Ruling: the mastery map's text on stages 3–4 (`--mastery-3`, `--mastery-4`) is `--on-accent`, on 0–2 `--text`;
  the visual check measures both per theme and the fix wave moves the split if any is below 4.5:1 (the home
  plan's month-tile rule) — cost: a mid-tone accent may need the split at 4.
- Ruling: a new `Select` base component is added here (not in #106) because the map's "Group by" is the first
  restyled page that needs one; #106 uses it everywhere — cost: one more component in `lib/ui`.
- Ruling: `stats` contract folder is web + Android only (no Go decoder) — the numbers are computed on clients
  only; the coverage guard needs a web test that names the fixture, which `summary.test.ts` is — cost: none.
