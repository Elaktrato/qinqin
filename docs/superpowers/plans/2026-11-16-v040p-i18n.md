**Public API for the extraction tasks (9–23) and the server/Android work (stable; change only with a Ruling):**

- `import { t, tParts, type MessageKey, getLanguage, getFormatLocale } from '$lib/i18n'`.
  `t(key, args?)` → string; `key` is a literal `MessageKey` (`keyof typeof en.json`, so `svelte-check` rejects an
  unknown key) or a value of a typed map `Record<X, MessageKey>`; never a template literal (catalogue test fails).
  `args` values are `string | number`; numbers/dates in `{name}` are pre-formatted with `$lib/i18n/format`; a
  plural's `#` is formatted by `t`. Never call `t` at module top level (call in a function, `$derived`, markup).
  Missing argument or unknown key: throws in dev/tests, `{name}`/the key in production.
- Rich text: `import Msg from '$lib/i18n/Msg.svelte'`; `<Msg key="sources.intro" args={{ n }}>{#snippet
  link(text)}<a href="/sources">{text}</a>{/snippet}</Msg>` — one snippet per tag name of the message; a tag
  without a snippet renders as its text.
- Formatting: `import { formatNumber, formatPercent, formatDate, formatDateTime, formatTime, formatDay,
  formatWeekday, formatRelative, formatRelativeFrom, formatList, formatDuration, languageName } from
  '$lib/i18n/format'` (each takes optional Intl options merged over its default). `Intl.*Format(`/`toLocale*String(`
  outside `lib/i18n` fails the lint.
- Key scheme: `area.part.name`, 2–6 lower-camelCase segments (`[a-z][a-zA-Z0-9]*`, no `_`/`-`), ≤ 120 chars,
  first segment from `KEY_AREAS` in `lib/i18n/keys.ts` = the README list. Keys are stable, never reused; a
  removed key goes to `docs/contracts/i18n/retired-keys.json`. `common.*` only for context-free words
  (`common.action.save`, …). API errors `apiError.<code camelCased>`; built-in plugins `plugin.<idCamel>.*`.
- Adding catalogue text for an area: (1) remove the area's files from `pending.json` `text` (and `intl` if you
  move their formatting); (2) add the keys to `src/lib/i18n/messages/en.json` keeping it sorted (tab-indented,
  trailing newline; a translator note in `messages/notes.json` where the context is not obvious); (3) replace the
  strings with `t()`/`<Msg>`, plurals as `{count, plural, one {…} other {…}}` (the whole message), no wording
  change; (4) add one area component to `SAMPLES` in `lib/i18n/pseudo.dom.test.ts`; (5) run
  `npx vitest run src/lib/i18n <area tests>` and `npm run check`. The guards: `hardcoded.test.ts` (text/intl/lang
  lint, stale pending entries, allowlist reasons), `catalogue.test.ts` (scheme, sorted, parses, every en key used
  as a literal in non-test `src/`, every literal key exists and its argument names match, no dynamic keys).
  A deliberate exception goes into `lib/i18n/allowlist.json` as `{file, text, reason}`.
- A new key area needs a line in `KEY_AREAS` and in the README's areas block (a test pins both).
- Languages: `SUPPORTED_LANGUAGES` in `lib/i18n/negotiate.ts` (`['en']`); `negotiate(candidates, supported)`,
  `formatLocale(interface, device)`, `isLanguageSetting(value)`; `loadCatalogue(lang)` (Task 28 calls it from the
  root `+layout.ts`); `installCatalogue`/`resetCatalogue` for tests only.
