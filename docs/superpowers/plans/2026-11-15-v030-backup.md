## Global constraints

- Every statement of a restore on `tx`; files written before commit into a staging directory, old
  files removed only after commit.
- No secret in any archive, log, response or fixture: the writer never selects from a table whose
  registry entry is `exportSkip`; tests grep archive bytes for seeded secrets.
- Error bodies `{"error":"<code>","message":"…"}`; new codes go into `docs/contracts/auth/errors.json`
  (accounts convention): `export_running`, `backup_version_unsupported`, `backup_invalid`,
  `backup_too_large`, `unresolved_entries`, `restore_running`, `backup_running`,
  `insufficient_storage`, plus the re-auth codes reused from self-delete.
- Archive names are never joined into a filesystem path; only integer ids build paths.
- Caps (constants in `backup/format.go`): upload 128 MiB, manifest 1 MiB, JSONL line 1 MiB, book file
  64 MiB, uncompressed total 2 GiB, ≤ 10 000 entries, events per file 100 000, plugin value 256 KiB.

## Rulings (plan-specific; spec rulings apply as written)

- Ruling: the export registry is a field on the accounts plan's `userTables` rows, not a second list —
  the spec's "one source": delete, export and restore cannot drift — cost if wrong: `delete.go` grows
  one field per row.
- Ruling: tickets are an in-memory store (`map[sha256hex]ticket`, mutex, janitor) — single process,
  60 s lifetime; a restart only invalidates pending downloads — cost if wrong: none.
- Ruling: staged restores live on disk under `<data>/tmp/restore/` (removed at start-up and by the
  janitor), status in memory — a restart loses a stage, the user uploads again — cost if wrong: one
  re-upload.
- Ruling: the restore shares the workspace-deletion statements through `*sql.Tx` helpers
  (`library.DeleteWorkspaceBooks`, `journal.DeleteWorkspacePhotosTx`, and new `*sql.Tx` helpers for
  events and plugin rows extracted from `deleteWorkspace`), not `plugins.beginImmediate` (unexported,
  `*sql.Conn`) — one transaction type for every step — cost if wrong: none.
- Ruling: the authorization matrix of accounts plan 1 gets an explicit exemption list for the two
  ticket download routes (`GET /api/account/export/{ticket}`, `GET /api/admin/backup/{ticket}`):
  they are unauthenticated by design and answer 404 for anything but a live ticket; a test asserts a
  restricted token gains nothing there — cost if wrong: none.
- Ruling: the 1M-event memory tests run only with `QINQIN_BIG_TESTS=1` (Task 17 runs them once) — they
  take minutes on 4 shared cores — cost if wrong: a memory regression is caught at the branch end, not
  per task.

## Review Focus

1. **No data outside the archive's promise:** export never reads an `exportSkip` table; secrets
   grep test; tombstones/pack sentences excluded; a second user's data never appears.
2. **Atomicity:** every restore statement on `tx`; staged files only moved after commit; failure
