# #180 — the tone-pair drill (2026-11-28)

Milestone v0.9.0, phase 5. Branch `feature/v090-180-tone-pairs` from `feature/v0.9.0` (0c531926, ContractVersion 25).
The first real drill on the drills framework (`docs/superpowers/plans/2026-11-28-drills-framework.md`,
`docs/contracts/drills/`).

## What (issue and owner decisions)

- Mandarin tones trained in pairs: the **20 two-syllable patterns** (1-1 … 4-5, `5` the neutral tone). A grid of the
  20 pairs; each pair practises real two-syllable words with that pattern, **from the learner's decks first, then
  the HSK word list**.
- **Exercise:** see the characters or hear the word (recording or device voice), mark both tones, immediate
  feedback. **Answers typed through the IME, with a choice fallback** (v0.9.0 plan).
- **Sandhi:** grade the **citation tones** by default. "Show tone sandhi" (on by default) shows the spoken tones
  beside the citation tones; "Grade spoken tones" (off by default) grades the spoken tones instead. Both per
  workspace; #300 built them for tone cards with the rules in `docs/contracts/tones/`: reused, not duplicated.
- **Per-pair accuracy** in the grid so weak pairs stand out, and a "practise my weakest pairs" session.
- **Reuse** the tone card's contour drawing and grading.
- A **drill** in the framework: item key `<t1>-<t2>` (the citation tones), its own event type `drill.tone-pairs`,
  registered so it counts as activity (heatmap, weekly summary, goals).
- Phone first (360 px, `phone-width.spec.ts`), hidden pinyin through `useRomanisation()`, the Android WebView with
  the keyboard kept up between items.

## Rulings

- Ruling: the **20 items** are `1-1` … `4-5` (first tone 1–4, second 1–5) in grid order, which is also the order
  new pairs are introduced; a pair is a candidate only while it has at least one word — the issue's 20 combinations
  (a neutral first syllable is not a pattern learners train) — cost if wrong: one more row of keys.
- Ruling: **a word gives a pair** when its written form is exactly two Han characters, it has at least one clean
  two-syllable pinyin reading, every clean two-syllable reading has the same citation tones, and the first is not
  neutral; otherwise it is left out (polyphones whose readings differ in pattern, erhua, mixed scripts) — the item
  is the citation pattern and the verdict accepts any reading, so an ambiguous word would grade one item against
  another's pattern; the 不/一 rules need the characters — cost if wrong: a few words fewer per pair.
- Ruling: **words**: the workspace's cards' entries (every kind, the first card of an entry, in card creation
  order) first, then the **installed HSK word list** read through the server (`GET /api/schemes`, the language's
  word-unit scheme: `hsk-words`, else another `hsk-` pack, else any word-unit level pack), level by level, until each
  pair has 12 words or the levels end; nothing is bundled or hand-written — the issue's order; the HSK pack is the
  server's (licence status per Data and licences, the owner's decision), the readings CC-CEDICT's (CC BY-SA); no new
  data and no word list of our own to review — cost if wrong: a workspace without a level pack practises only deck
  words.
- Ruling: the words are kept for the session (`session.caches.tonePairWords`, by language) — the Practice page loads
  on every route change; the level lists change only on a re-install — cost: a word added to a deck during the
  session appears after a reload.
- Ruling: **which word a question asks**: the pair's words in order, the next one after each answer
  (`words[answers % words.length]`) — each round shows a new word of the pair, deck words first — cost if wrong: a
  learner meets the same word again only after the pair's other words.
- Ruling: **grading** is the tone card's `toneVerdict` with the workspace's `gradeSpoken`: by default the citation
  tone or the spoken tone of each syllable is right (the tone contract: a sandhi tone is not a mistake); with "Grade
  spoken tones" only the spoken tone — the owner's "citation by default" as #300 settled it for tone cards; one rule
  for both — cost if wrong: a learner who marks 2-3 for 你好 is right by default.
- Ruling: the **item stays the citation pair** when spoken tones are graded (你好 is item `3-3` either way) — the
  contract's planned key is the citation pair; the grid groups words by their dictionary pattern — cost if wrong:
  3-3 accuracy also measures the sandhi.
- Ruling: **grade**: both tones right is Good (3), anything wrong is Again (1); no Hard, no Easy — one syllable
  wrong is a wrong pair; nothing in the question is a hint — cost if wrong: FSRS sees fewer shades.
- Ruling: one **mode** `mark` (read or hear the word, mark both tones) — a listening-only mode (characters hidden)
  is not asked for; it would be a second mode of the same items — cost if wrong: none, a mode can be added.
- Ruling: **the answer field**: a text field that takes the two tones as digits (`3 4`, `34`, `3-4`; `0` and `5` are
  the neutral tone), numbered pinyin (`ni3 hao3`: its digits) or tone-marked pinyin (`nǐ hǎo`, needs a mark); on a
  phone it opens the digit keyboard (`inputmode="numeric"`); Enter checks, and after the answer Enter goes on. The
  **choice fallback** is the tone card's row of five tone buttons per syllable, which fill the field — the plan's
  "typed through the IME with a choice fallback"; digits are what a learner types for tones, and the IME's digit
  pad needs no switching — cost if wrong: a learner who types pinyin on a phone switches the keyboard to letters.
- Ruling: **the keyboard stays up**: the field is never disabled or remounted; after the answer it is read-only and
  keeps the focus, the next item clears it — the framework keeps the question mounted; a disabled field would drop
  the focus and the phone keyboard — cost: none.
- Ruling: no swipe pads in the drill — the pads take a 110 px square per syllable and their pointer capture fights
  the text field; the tone buttons are the tone card's tap path and the contours are drawn for the chosen tones and
  the answer — cost if wrong: a learner who likes swiping uses the tone cards.
- Ruling: **sandhi shown**: with "Show tone sandhi" on, a sandhi syllable's answer shows citation → spoken (`nǐ →
  ní`, or `3ˇ → 2ˊ` with contours when pinyin is hidden); off, citation only. The prompt says what is graded: by
  default "Mark the dictionary tones; a tone-sandhi tone also counts", with "Grade spoken tones" "Mark the tones as
  spoken (with tone sandhi)" — as the tone card — cost: none.
- Ruling: **hidden pinyin**: the drill works the same; the prompt is the characters (every word has one character per
  syllable), the answer shows tone numbers and contours, never pinyin letters, also not in accessible names; the grid
  and the round summary name pairs by tone numbers; a tone-marked answer the learner types is still read — the
  owner's #284 rule for tone cards; the tones are the exercise, the pinyin letters are not needed — cost if wrong:
  none.
- Ruling: **audio**: a play button with the word's recording or the device voice (the workspace's audio settings),
  before and after the answer — hearing the word is the issue's "hear the word"; the play button shows no reading —
  cost: a learner can listen before answering (that is the exercise).
- Ruling: the **grid** sits on the Practice list under the drill (a framework hook `DrillDef.overview`): 4 rows
  (first tone) × 5 columns (second tone); each cell shows the pair, its accuracy over its **last 10 answers** and a
  word state in words (new, weak below 60 %, fair below 85 %, strong) — not colour only; a pair without words is
  dimmed — recent answers say how the pair goes now; ten is a round's worth — cost if wrong: two constants.
- Ruling: **"Practise my weakest pairs"** is a drill's own weakest round, a framework route
  `/practice/<drill>/weakest` (pick.json `weakest` over one drill), linked from the grid once a pair has an answer —
  the framework's round across drills already has the pick; one drill is the same pick with one candidate — cost if
  wrong: none.
- Ruling: the drill **applies** where the language profile has tones (`zh`, `zh-Hant`), the same test as the tone
  settings — the sandhi rules are Mandarin — cost: none.
- Ruling: the contour drawing moves to `lib/components/ToneContour.svelte` and the contour paths to
  `lib/exercises/tones.ts` (`TONE_CONTOURS`); the tone card uses them — record 0004: a widget of two features sits in
  `lib/components`; logic shared with a drill sits in `lib/exercises`, never in flashcards — cost: none.
- Ruling (made while building): **zh-Hant** workspaces read a level list of exactly their language, as the system
  decks do (`levelDecks`); with only the `zh` HSK pack installed, a zh-Hant workspace practises its deck words — one
  rule for which level lists a workspace sees — cost if wrong: zh-Hant learners without decks see "Nothing to
  practise" until a zh-Hant list exists.
- Ruling (made while building): the level list is read **at most 4 levels deep** (HSK 1–4) and stops once every pair
  has 12 words — the 7–9 band alone has thousands of words; every pattern occurs in HSK 1–2 — cost if wrong: a rare
  pattern has fewer words.
- Ruling (made while building): a tap on **Check**, on a **tone button** or on the round's **Next** leaves the focus in
  a focused typed field (`pointerdown` default prevented only while a text field has the focus), and a new word
  focuses the field when nothing has the focus — the phone keyboard stays up through a whole round; buttons used
  without the field behave as usual — cost: none. The Next part is a framework change (`RoundView.svelte`), for every
  drill with a typed answer.
- Ruling (made while building): a registered drill's activity words are **literal keys** in `DRILL_WORDS`
  (`activity/sources.ts`) — the framework built them at run time, which the catalogue check ("every en key is used as
  a literal") cannot see, so the first registered drill failed it; a test now checks one pair per registered id —
  cost: one line per drill.
- Ruling (made while building): the round summary names an item by its word and pair (`你好 (3-3)`), no reading —
  characters are not romanisation — cost: none.
- Ruling: ContractVersion **26** (25 on the base; the orchestrator renumbers): the registry gains `tone-pairs`, a new
  fixture `tones/pairs.json`.

## Framework gaps found and fixed here

1. A drill's words for activity were built as dynamic catalogue keys (`activity/sources.ts`): invisible to the
   catalogue check, so registering any drill failed `catalogue.test.ts`. Now `DRILL_WORDS`, literal, with a test
   (`sources.test.ts`, seen failing first).
2. No place for a drill's own overview on the Practice list (the issue's grid): `DrillDef.overview`, with the Practice
   data's `answers` (`PracticeList.dom.test.ts`, seen failing first).
3. No per-drill weakest round (the issue's "practise my weakest pairs"): `/practice/<drill>/weakest`
   (`route.test.ts`, `PracticePage.dom.test.ts`, seen failing first).
4. The round's Next button took the focus from a typed field on a tap, dropping the phone keyboard between items:
   `pointerdown` kept from taking the focus while a text field has it (`TonePairs.dom.test.ts`).

Checked end to end in e2e (the framework's local follow-up item 3, as far as a browser can): with the first
registered drill, `GET /api/stats/activity` lists `drill.tone-pairs` and gives 3 points for 3 answers, the goal
picker (Settings → Study, "Count") offers "Tone pairs", the Stats heatmap shows the source, the weekly summary has a
"Tone pairs" row, and Practice is in the navigation of the Chinese workspace (not of the Japanese one).
